# Unsigned dependency verification candidate

Main audit based on `e1e723fc3ba862ffe10626cd732c8af0c38d775a`; GPT-6 / Codex desktop, exact variant/effort not reported: implementation and source self-review, not independent review.

The Dependency inventory workflow gains an explicit manual `verification_candidate` boolean, default false. Ordinary pushes retain inventory-only behavior. Opt-in execution compiles both app variants, runs both unit suites/lint and compiles the baseline generator, with build-cache reuse disabled and tasks rerun. It generates SHA-256 verification metadata using pinned Gradle's supported flag, without dry-run, real signing keys, APK publication or write-token access. Validated/serialized public XML (comments and processing instructions omitted) plus a commit-bound receipt are the only candidate artifact files. Existing action pins, Java/wrapper/distribution/SDK guards and normal signed workflow stay intact.

Gradle generation observes repository/cache bytes; it does not independently authenticate the publisher. The candidate is clearly named UNTRUSTED, is not committed as `gradle/verification-metadata.xml`, and does not enable verification in production CI. Never copy it into an enforcing policy merely because this run passed. Candidate XML validation requires metadata checking, checksum-only default configuration, complete SHA-256 records, public coordinate/basename fields and bounded UTF-8/regular-file input; refuses DTD/entities, exemptions and unknown structures. No credential/cache/log glob is uploaded.

This deliberately does not claim full coverage: signing/assembly, the conditional diagnostic helper, every task-time/detached resolution, generated/transformed caches and SDK/JDK executable trust remain separate. The baseline generator compile adds task-time coverage but does not run a phone/profile journey. Version locking and publisher key/checksum approval are still unresolved. A future reviewer must compare this candidate with independently authenticated artifacts/metadata and an approved trust basis before strict admission.

Checked official Gradle 8.13.0 dependency-verification userguide source: https://github.com/gradle/gradle/blob/v8.13.0/platforms/documentation/docs/src/docs/userguide/dep-man/other/dependency_verification.adoc . Generation runs supplied tasks and collects observed artifacts/metadata; dry-run misses task-time resolutions. The source also warns that existing dependencies may already be compromised. No local Gradle/SDK build executed.

Local candidate exporter/abuse-case, wrapper and distribution guard tests run; exact-head normal Android/inventory CI plus opt-in actual candidate dispatch pending. Device QA not needed for this workflow-only change. Build/dependency trust stays an open gate, not phone acceptance. No Stable release or experimental changes.
