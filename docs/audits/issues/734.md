# #734: AVI header and index admission

Updated 2026-10-28. Branch `codex/avi-header-admission-oct28` from `d7746824` (main205 plus the verified ID3 prefix work, #705). Post-RC, outside the frozen release candidate. No phone, no user media, and no OOM, crash or exploit has been demonstrated.

## Source finding (pinned Media3 1.11.0)

Extractor sources SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`. Root's independent source assessment came first; this implementation follows it.

- **Header read.** In `AviExtractor`, `STATE_READING_HDRL_HEADER` reads 12 bytes at position 12. Its nested ChunkHeaderHolder checks LIST; the outer state checks hdrl and keeps the size as a signed int. Root initially suspected a non-LIST bypass by overlooking the nested helper, then withdrew that finding after reading populateWithListHeaderFrom. The original guard filter was correct; no such native bypass is claimed.
- **Body read.** The next read allocates `size - 4` bytes before reading the body. That `int` arithmetic is negative for small sizes, and wraps to a huge positive array from `Int.MIN_VALUE`.
- **LIST parse.** `ListChunk.parseFrom` recurses through child LISTs while `bytesLeft() > 8`, so a short tail is ignored and RIFF pad bytes are not skipped. Child sizes are only bounded by the whole array: a child can read across its parent, and a negative size steps backwards. Count and depth are unchecked.
- **Streams.** `parseHdrlBody` runs `processStreamList` for each top-level `strl`. For each audio or video stream this creates a track and a `ChunkReader`, which preallocates fixed index arrays.

## Guard

- **Where it runs.** `AviHeaderAdmission` is wired only for the actual `AviExtractor`, on `MetadataBoundedExtractor.read` and `seek`. The initial ID3 prefix check still runs for every candidate. The native AVI sniff is only 12 bytes, so no sniff change.
- **Header.** On the native header read at position 12, the declared body is admitted before it is allocated. A size under 4 is malformed. The body must fit `hdrlBytes`, and when the stream length is known the body must fit inside it.
- **Body.** When that exact body has been delivered, its LIST structure is checked before `ListChunk` parses it:
  - native's `> 8` loop is mirrored;
  - a child crossing its parent, or a negative size, is refused as malformed;
  - total chunks, LIST depth and top-level `strl` streams are counted.
- **Retries and seeks.** A failed body read keeps the admitted size for the native retry, and every completed body is checked again; the header size remains available after a scan, not a cached body certificate. A seek clears the pending body, matching native: a seek to 0 either rereads hdrl from its header or skips it.
- **Cancellation.** Checked only before a watched read consumes input, so retry positions and native state stay aligned.
- **Refusals.** The existing sanitized `StreamMetadataRefusal`. Root added the existing optional audio-format message while preserving default tag copy.

Limits are proposals, not measured safe memory: `AviHeaderLimits(hdrlBytes = 16 MiB, chunks = 4096, depth = 16, streams = 128)`, an optional last constructor parameter so tests can tighten them. There is no parser fork and no private production API.

Known-length backing is checked. Unknown negative search chunks refuse instead of seeking backwards to the same header.
- Sample chunks, old/new array coexistence, global heap and decoder behavior remain unmeasured; byte/row policies are proposals.
- Codec data in `strf`: at most 64 KiB per stream, bounded by the hdrl body.
- `suggestedBufferSize` → max input size, and decoders.

This is not whole-AVI or whole-heap clearance.

## Tests and status

`AviHeaderAdmissionTest` uses the actual default `AviExtractor` and honours `RESULT_SEEK` by reopening the source:

- **Raw control.** An unbacked 128 KiB hdrl body is allocated, observed as the native read target, before `EOFException`.
- **Guarded refusal.** Before any body array is created: by the budget (unknown length), by the stream length (known length), and for sizes -1, 3 and `Int.MIN_VALUE`.
- **Real fixture.** Through `PlaybackExtractors`: format, sample rate and channel count, the seek map, a mid seek and a seek to 0.
- **Budgets and damage.** Depth, chunk and stream budgets, with within-limit controls, plus a crossing child and a negative size. All are refused before any native track or `endTracks`.
- **Retry.** An interrupted body retry with unchanged bytes plays; with a damaged first child size it is refused.

Synthetic header snippets are not encoded media. Fixture extraction is demux only, not audio decoding.
