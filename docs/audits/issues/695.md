# #695 — ReplayGain hints and reusable live IDs

Updated 2026-10-25. [Issue #695](https://github.com/averylicious/muon/issues/695). Inspected main `f0a744273e58645490a1f918a807ad2447d64662`. Isolated implementation branch `codex/live-gain-identity-oct25`; outside frozen RC .1420, which is untouched. No phone or music-file changes.

## Finding and correction

`PlaybackService` previously reused an exact remembered attenuation keyed by endpoint/numeric Tauon ID even when the current selected audio had no gain tag. A reused ID could therefore keep the previous file's attenuation. This source-level finding was already noted in the October 4 loudness report; there is no audible/device reproduction or amplification claim.

The candidate uses the selected audio's actual parsed/applied gain when available, otherwise the existing library median for live audio. It reads the current selected Tracks at each transition/play-state/settings callback, so repeat-one does not erase a valid tag and untagged/empty tracks cannot retain a prior parsed value. Canonical saved-copy handles retain their existing exact hint, and all remembered history remains intact and contributes to the estimate. A handle is a locator, not authentication or proof of unchanged bytes; this does not redesign saved-copy identity. No preference schema, arbitrary history cap, tag scanning/writing or output-volume change.
