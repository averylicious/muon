## Finding and correction

The service could reuse exact attenuation keyed by endpoint/numeric Tauon ID even when the current selected audio had no gain tag. A reused ID could therefore keep the previous file's exact gain. This source finding was noted in the [earlier loudness report](../2026-10-04-loudness-volume-source.md); no audible/device reproduction or amplification claim.

Use the current selected audio's parsed/applied gain, otherwise the existing library median for live playback. Read `player.currentTracks` at transition/play-state/settings callbacks: repeat-one need not emit another tracks-change event, so listener-cached state is insufficient. Canonical saved-copy handles retain their stored hint; all gain history stays intact and contributes to the estimate. Handles are locators, not authentication or proof of unchanged bytes. No schema, arbitrary history cap, scanning/tag writing or Android output-volume change.

The latest API cleanup makes raw exact-hint fallback private and routes `volumeFor` plus the service through the same current-audio policy. Retained-history assertions and all existing test cases remain; callers cannot accidentally reuse the old live-ID volume behavior.
