## Confirmed scope gap

`PlaybackSessionCallback.savedAdmissionPending` was per callback. `PlaybackService` creates a new callback/executor on creation and uses graceful executor shutdown on destruction, which lets old queued/running work finish. If saved-source admission remains unfinished across a same-process service replacement, another callback could enqueue another bounded request. Repeating owners bypasses the intended single-pending-work budget. This is conditional source evidence, not a measured phone leak/OOM; force-stop/process death clears the process and is not this scenario.

## Candidate

Only the pending flag moves to the callback's private process-shared companion. It remains held through actual task exit after cancellation, or is released on the production executor's known pre-acceptance rejection. No new executor, timeout, source access or schema is introduced; the service keeps graceful shutdown. Live-only requests bypass saved admission as before. UID/URI/input-budget/source checks, saved-copy membership checks, queue behavior and persisted data remain.

This bounds pending saved-check work across owners, not all service threads, opaque Binder bytes or total heap. Playback already loaded before the request is not modified by refusal. A new saved request may correctly report busy until the old task really exits; no false cancellation-based release.

## Verification / next action

One focused addition uses distinct real production callback instances and controlled workers with the existing Media3 session. Cancel a queued old request, require both old/new owners to refuse another saved check without queueing; live-only admission still works. After the old task actually exits, admit the replacement; while its read is active another owner's request must refuse, then both can retry after exit. The test cancels/drains held work even on assertion failure, without a production reset hook. Existing cancellation/rejection/failure/current-queue checks remain.
