## Confirmed route / evidence

Pinned Media3 `Id3Peeker.peekId3Data` allocates a declared full tag array before reading its body. `maxTagPeekBytes` limits search for a header, not tag length. `FlacExtractor.sniff` calls the same peeker even with parseData=false, so an MP3-only wrapper would run too late in the default candidate list. Disabling artwork/ID3 parsing does not prevent that allocation. A huge/malformed leading ID3 declaration can therefore exceed Muon's later artwork caps. No phone OOM, exploit or #671 root cause is claimed.

Published Google Maven extractor1.11.0 sources SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`: Id3Peeker, FlacMetadataReader, Mp3Extractor, default factory and forwarding APIs. Exoplayer1.11.0 sources SHA256 `2d583de9d39b48e45f9a29f1d94d23032c0642cfc7ca4bbe1967071d26a60ed6`: BundledExtractorsAdapter retains wrappers for sniff/read, including the single-candidate no-sniff path; DefaultMediaSourceFactory configures the delegated factory without replacing the wrapper. ParserException is permanent to its default load-error policy.

## Candidate / tradeoff

Before any default extractor sniff or initial read, admit at most4MiB of leading ID3 prefix (tags and intervening MP3 search padding). Check each declared end before body peeking/skipping or invoking the native peeker. MP3 gets the pinned128KiB header-search behavior; other format candidates inspect only initial consecutive tags, avoiding false matches in arbitrary non-MP3 payload. Reset the peek position in finally and preserve read position, factory ordering/options, underlying identity and seek/release forwarding.

Oversized or malformed metadata returns a fixed, actionable parser error rather than retrying indefinitely; no private URI/tag content is rendered. Valid files with unusually large embedded tags may now be refused and need smaller artwork/tags. This is an admitted-prefix limit, **not** a whole decoder/heap guarantee or a bound on every container's metadata. Muon's streaming and saved routes share this source factory; copies remain unchanged/readable by other tools. No new dependency or storage-format change. ID3 ReplayGain parsing is a separate fix #702/#703.
