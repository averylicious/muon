## Finding and implementation

Pinned Id3Peeker allocates a declared tag array before its body; decoded MLLT tables/seeker arrays, recursive chapters and text/CTOC values can cost substantially more than the tag bytes. Native unsynchronization repeatedly copies the remaining region. Official inspected extractor1.11.0 source SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`; exoplayer source `2d583de9d39b48e45f9a29f1d94d23032c0642cfc7ca4bbe1967071d26a60ed6`.

Prefix admission runs before every actual default candidate's initial sniff/read, including FLAC, and resets peeks afterward. Decoded admission observes the actual peeker body before native decode, using a bounded private copy. Supplemental/wrapped ID3 uses a supplied public decoder/renderer factory: preserve default slots/order/other renderers; drop optional metadata on policy refusal and restore interruption. Respect delivered buffer limits and ordinary trailing padding.

Policies:4MiB cumulative prefix,4,096 tags/frames/text-or-CTOC values,16 chapter levels,1,048,576 total MLLT rows and4GiB estimated native shifted-byte work per tag. The work allowance is not input size or an elapsed-time guarantee. Nested malformed parent crossing refuses deliberately. Supplemental sample buffers already exist before decoder admission; no prior-buffer, every-container/codec, transient-GC or global-heap certificate.
