## Confirmed source / impact limits

Published container1.11.0 sources SHA256 `655d0a470126610cceeec1122665d87b041d36942be4eaaab1e01ceb4504fdbd`, `VorbisUtil.readVorbisCommentHeader`: unsigned comment count is cast to Int and used for a String array before remaining-payload/count validation. A large positive count can request a large array even in a short malformed header; a high-bit count becomes a negative array size. This parser is called by pinned Ogg Opus/Vorbis and native FLAC readers. OggPacket also grows a packet across pages without Muon's own metadata-byte limit.

Extractor1.11.0 source SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`; exoplayer1.11.0 source SHA256 `2d583de9d39b48e45f9a29f1d94d23032c0642cfc7ca4bbe1967071d26a60ed6`. **Loader.run explicitly catches OutOfMemoryError**, reports UnexpectedLoaderException and fails playback; its default policy does not turn that into an endless retry. No app crash, exploit, actual memory pressure or #671 cause is established. Trusted-LAN/file-data assumptions remain. Muon's #704/#705 ID3 prefix guard and later artwork caps do not cover this earlier container-specific allocation; they never claimed a universal decoder guarantee.

## Nested picture allocation boundary

Fresh pinned-source review on2026-10-27 also found PictureFrame.fromPictureBlock allocates byte[pictureDataLength] before checking the bytes remaining. This is called by native FLAC picture blocks and base64 METADATA_BLOCK_PICTURE Vorbis comments. A bounded outer block/packet alone therefore does not bound this nested declared allocation. The Vorbis adapter catches RuntimeException for a bad picture; Loader separately catches OOM. No actual OOM/crash is claimed.

A second tiny characterization checks a three-byte valid picture payload, a41-byte high-bit/negative length through the actual PictureFrame helper, and the Vorbis adapter's actual caught-negative behavior. It requests no huge allocation and does not decode an image. Both cases passed at `96ad498d4b9c7aa763646e1d98a0773e2f7c110a` / [Android .1502](https://github.com/averylicious/muon/actions/runs/40448057689): downloaded1,823 cases/variant, zero failures/errors/skips, lint0errors/65warnings plus3hints. Earlier .1494 covers the count/reader case only. Production admission must account for nested declared lengths before calling these parsers, while preserving valid artwork.

## Safe characterization / next engineering

One actual pinned-helper test uses a16-byte valid control with two empty comments, then an8-byte header whose count has its unsigned high bit set. Expect NegativeArraySizeException at array construction, position8 and no unread body, with no large allocation. This records the raw dependency boundary, not desired application behavior or an implemented refusal. It must not be mistaken for a safety test that clears #714; a dependency fix may legitimately change its expected raw exception.

The same test also constructs a91-byte Ogg/Opus stream and reaches the unchecked count through the actual OggExtractor/OpusReader path. Its page CRCs are placeholders: this pinned extractor does not validate them. This checks this reader route, not a fully standards-conformant file, CRC validity, audio decode or heap pressure. Final proof candidate `f4e16754390b7f3eaab7a6394dfdfd2d60826aa5` / [#715 .1494](https://github.com/averylicious/muon/actions/runs/40132886691) passed: downloaded1,822executions/variant, zero failures/errors/skips, lint0errors/65warnings plus3hints. The complete helper+91-byte real-Ogg case executed in both variants. CI was the first compile; no local Android build or OOM attempt. Earlier22a8b9fb/.1493 is superseded helper-only source, not verification of the real-extractor follow-up. Implementation should separate native FLAC block admission from Ogg packet/page admission. `FlacMetadataReader.readMetadataBlock` allocates complete comment/picture/seek blocks after a24-bit declared length; validating only the later String count cannot bound that earlier byte array. OggPacket.ensureCapacity runs before Opus/Vorbis header parsing; a guard after packet assembly is too late for its buffer growth. A start-of-stream-only preflight also does not bound later malformed audio packets. Preserve seek/retry/input identity, multiple metadata blocks, continuation/lacing and legitimate ReplayGain; scope any policy guarantee precisely rather than promising a universal decoder bound.

A narrow official Google Maven1.11.1 patch-source check found container/VorbisUtil.java and extractor/ogg/OggPacket.java byte-identical to pinned1.11.0. Container1.11.1 archive SHA256 `655d0a470126610cceeec1122665d87b041d36942be4eaaab1e01ceb4504fdbd`; extractor1.11.1 archive SHA256 `547129d7df7ef9cc3d2622036d3880ab205e5fe3241095049b39c6632c64bc4a`. That selected patch is not a fix for these two source boundaries. No dependency upgrade occurred and no claim about every newer/upstream version follows.

After exact-head proof, design bounded container-specific metadata/count admission **before** these parser/packet allocations, or qualify a compatible upstream fix. Keep legitimate vendor/comments, ReplayGain, format sniffing and seeking; do not truncate whole audio, casually fork/shadow library classes or add a count-only helper without wiring it into the actual route. Tests for the eventual guard must exercise real supported container paths and preserve valid files. Future opt-in/size tradeoffs need explicit acceptance; no new frozen-RC gate.

## Production admission candidate (branch `codex/container-metadata-admission-oct27`)

Candidate `ef5b632b16b07c0ea39518f54957692ef041ca21`, based on main `20579cf1` plus #705/#715 only. [Android .1504](https://github.com/averylicious/muon/actions/runs/40451576758) passed: downloaded1,837cases/variant, zero failures/errors/skips, lint0errors/65warnings plus3hints. All nine real-extractor tests and both prerequisite suites executed in both variants; Branch direction passed. This verifies JVM demux/metadata behavior, not device listening/codec memory. It is wired through the existing `PlaybackExtractors`/`MetadataBoundedExtractor` and Media3's public forwarding input/output classes, with no fork. Underlying extractor identities, factory order/options and the4MiB ID3 prefix guard are unchanged.

- **Native FLAC:** follows the actual `fLaC` marker read and each 4-byte block-header peek at the next expected offset. Seek-table, comment and picture declarations are refused at their header when cumulative declared payload would exceed16MiB; each allocated array is that payload plus4 header bytes. A completed comment or picture block is checked in the reader's own exact array range before the parser runs: comment count and lengths, nested Base64 `METADATA_BLOCK_PICTURE` and native picture data length. Padding and other skipped blocks are followed by actual consumption, never peeked or charged. Interrupted reads retry the same block; `seek(0)` resets the tracker.
- **Ogg:** each extractor read may deliver at most16MiB. The count persists across an interrupted read and resets only on a normal return or seek. Because OggPacket grows its array before our read hook, one packet array can reach16MiB plus one page-run (65,025 bytes), with the old and new arrays briefly coexisting. While headers are read, the actual page-header peeks and OggPacket runs are mirrored; when a run ends an OpusTags or Vorbis comment packet, the reader's actual assembled array is checked before the Opus/Vorbis reader parses it. That covers a reopen at a nonzero offset with different bytes. `seek(0)` rechecks headers only before the seek map is published, matching `StreamReader`. Ogg FLAC keeps the byte bound; it has no comment parser here.
- **Entries:** at most4,096 comments and pictures per song's metadata, in addition to the structural count ≤ remaining bytes ÷4.
- **Refusals:** the existing fixed "too large" and "invalid" messages. Behaviour changes for user acceptance:
  - FLAC/Ogg files over these budgets fail;
  - an Ogg picture whose declared data length exceeds its bytes now fails the song, where Media3 dropped it;
  - a header that cannot be mapped to observed pages fails as invalid.
- **Not covered:** decoder/codec memory, STREAMINFO's maximum frame size used as a decoder input size, MP4/WAV/other containers, or a general heap guarantee.

Nine focused tests use real extractors and the original fixtures: valid FLAC/Opus/Vorbis keep ReplayGain and artwork through the factory and duration seeks; large padding stays uncharged and unpeeked; malformed counts, entry overflow and nested/native picture lengths are refused before parsing; oversized and cumulative blocks are refused at their headers; an interrupted FLAC block resumes and `seek(0)` rechecks; an Ogg continuation keeps its bound across an interrupted retry; a partial OpusTags reopened with different bytes is refused; `seek(0)` rechecks only before seek-map publication; factory and single-candidate reads refuse malformed fixtures. Demux and metadata only: no audio or bitmap decoding, heap pressure or device test.
