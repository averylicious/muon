## Confirmed source / impact limits

Published container1.11.0 sources SHA256 `655d0a470126610cceeec1122665d87b041d36942be4eaaab1e01ceb4504fdbd`, `VorbisUtil.readVorbisCommentHeader`: unsigned comment count is cast to Int and used for a String array before remaining-payload/count validation. A large positive count can request a large array even in a short malformed header; a high-bit count becomes a negative array size. This parser is called by pinned Ogg Opus/Vorbis and native FLAC readers. OggPacket also grows a packet across pages without Muon's own metadata-byte limit.

Extractor1.11.0 source SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`; exoplayer1.11.0 source SHA256 `2d583de9d39b48e45f9a29f1d94d23032c0642cfc7ca4bbe1967071d26a60ed6`. **Loader.run explicitly catches OutOfMemoryError**, reports UnexpectedLoaderException and fails playback; its default policy does not turn that into an endless retry. No app crash, exploit, actual memory pressure or #671 cause is established. Trusted-LAN/file-data assumptions remain. Muon's #704/#705 ID3 prefix guard and later artwork caps do not cover this earlier container-specific allocation; they never claimed a universal decoder guarantee.

## Safe characterization / next engineering

One actual pinned-helper test uses a16-byte valid control with two empty comments, then an8-byte header whose count has its unsigned high bit set. Expect NegativeArraySizeException at array construction, position8 and no unread body, with no large allocation. This records the raw dependency boundary, not desired application behavior or an implemented refusal. It must not be mistaken for a safety test that clears #714; a dependency fix may legitimately change its expected raw exception.

CI is the first compile; no local Android build. After exact-head proof, design bounded container-specific metadata/count admission **before** these parser/packet allocations, or qualify a compatible upstream fix. Keep legitimate vendor/comments, ReplayGain, format sniffing and seeking; do not truncate whole audio, casually fork/shadow library classes or add a count-only helper without wiring it into the actual route. Tests for the eventual guard must exercise real supported container paths and preserve valid files. Future opt-in/size tradeoffs need explicit acceptance; no new frozen-RC gate.
