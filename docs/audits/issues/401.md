## Post-RC Move-completion admission candidate

Inspected main `dd8782a0426437093a99ea3f7205878b6af775bc`. Legacy `finishReadyMoves` enqueued one saver closure per ready receipt on every settled completion/idle callback, before any check claimed the receipt. While the saver is busy, repeated callbacks can therefore retain duplicate verification jobs. This is source-level queue amplification, not a reproduced OOM or proof of the historical partition-storage latency's cause. Native receipt capacity bounds unique receipts, not duplicate queued closures.

Branch `codex/move-completion-admission-oct25` reserves one per-Store pending/running sweep before enqueue. Repeated callbacks set one retry bit; a main-thread continuation rechecks quiet managers/current receipts after the worker releases its slot, preventing a lost final callback. The worker reads the current ready list rather than retaining a list per event. Capture application context.
