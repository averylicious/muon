## Confirmed boundaries and behavior

Native strings/binaries and unknown-length sniffing can allocate before declared-body delivery. The implemented observer also bounds selected metadata/track/chapter/cue/native-master retention and known-text packets. Root compared all30 pinned native master IDs with the observer: exact set match. [Design and limits](../2026-10-27-matroska-admission.md).

Separate Xiph path: native binaryElement increments headerSize for every actual255 byte; readScratch doubles its array before another input read, before sampleData. The native32/32KiB unfinished-header control confirms destination growth and zero audio delivery at EOF. This uses actual delivered bytes, not tiny-declaration amplification. Progressive loading-interval checks are outside that native read, and the scratch is outside SampleQueue allocation. EOF, non255 bytes, I/O errors or interruption can stop it; no indefinite hang or phone OOM is established.

The new scalar Block marker refuses only pinned one-byte scratch-extension requests at offsets4+ beyond64KiB. Requested offset, not retained array capacity, avoids poisoning a later small header after seek. No output wrapper/map, payload copy or lacing parser. Audio bodies use DataReader.read; known subtitle-body reads retain their separate4MiB cap; small encryption/NAL reads are unaffected in the inspected pinned routes. Backing can double before interception; old/new arrays and whole heap are not byte-exact bounded. New native controls cover both Block variants/audio/text/seek refusal, completed Xiph delivery and large ordinary audio/subtitle bodies under a tiny injected header budget.
