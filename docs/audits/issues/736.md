## Source finding (pinned Media3 1.11.0)

Extractor sources SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`. Root reported these two files unchanged in 1.11.1. Root read all of `FlvExtractor.java` and `ScriptTagPayloadReader.java` first; the implementation rechecked them.

- **Sniff.** `FlvExtractor.sniff` peeks the 9-byte header, then calls `advancePeekPosition(dataOffset)` from a signed 32-bit header field. That grows the input's peek storage before the first previous-tag-size bytes are confirmed.
- **Read path.** `readFlvHeader` skips `dataOffset - 9 + 4` before the first tag header. A single-candidate factory reaches this without sniffing.
- **SCRIPT body.** A SCRIPT tag is buffered only while `outputSeekMap` is false. `prepareTagData` may allocate `max(capacity * 2, size)` from the 24-bit tag size before the body is read, and the array is reused across tags.
- **AMF parse.** For `onMetaData` with an ECMA value, `ScriptTagPayloadReader`:
  - creates `HashMap(count)` per ECMA array (capacity only; this is not proof of an eager table);
  - creates `ArrayList(count)` per strict array, which allocates its element array;
  - recurses through objects and arrays with no depth limit;
  - reads past the tag's delivered limit into stale reused bytes, or out of bounds.

## Guard

- **Where it runs.** Only the actual `FlvExtractor`, through public hooks on `MetadataBoundedExtractor`: sniff, init, read and seek. AC-4 behaviour and the initial ID3 prefix check (every candidate) are unchanged.
- **Sniff.** It reuses AC-4's requested-lookahead input, now extracted as `sniffWithinLookahead`; `sniffAc4` keeps its name, defaults and semantics. At the limit it returns false so other candidates can try. A known-length file keeps its ordinary EOF.
- **Startup.** On the native 9-byte header read at position 0:
  - a data offset under 9 is malformed;
  - a data offset over the lookahead limit is refused;
  - with a known length, the offset plus the 4-byte previous tag size must lie inside the file.

  This adds no new version or magic check.
- **SCRIPT tags.** On each native 11-byte tag header read, a SCRIPT tag that will be buffered has its declared body admitted before `prepareTagData` can allocate: within the budget, and backed by a known length.

  When that body has been delivered (only its delivered length, never the reused array's capacity), the exact native `onMetaData` path is walked before `ScriptTagPayloadReader` parses it:
  - every read must be backed;
  - ECMA and strict-array counts reserve their declared capacity once, after a physical minimum (3 bytes and 1 byte per entry), and object entries reserve as they are found;
  - depth is checked;
  - unsupported types consume nothing, as native.

  Other names, a non-ECMA metadata value and an empty value are ignored, as native. Every delivered body is scanned, including an I/O retry; nothing is cached as safe.
- **After a seek map.** A forwarding `ExtractorOutput` records a successfully forwarded seek map, which also persists across seeks as native's flag does. After that, scripts are skipped natively and are not inspected.
- **Audio and video tags.** Left entirely native. Reader presence affects no SCRIPT decision, so it is not tracked.
- **Cancellation.** Checked only before a watched read consumes input.

Limits are proposals, not measured safe memory: `FlvMetadataLimits(lookaheadBytes = 16 MiB, scriptBytes = 4 MiB, slots = 65,536, depth = 16)`. They are an optional last constructor parameter so tests can tighten them.

## Deliberately stricter

These are refused as malformed where native would read stale or out-of-bounds bytes:
- AMF data not backed by the delivered body;
- a count with its top bit set;
- a data offset under 9.

## Remaining, not covered

- Audio and video tag payloads and their reused buffer, which can grow beyond the script budget.
- AVC and AAC configuration, codecs, decoders and sample queues.
- The global heap.
- The exact keyframe array size beyond the reserved slot upper bound.
- `HashMap` table growth is bounded only through those reserved slots.

`TagPayloadReader` and `ExtractorOutput` were not in the expanded sources. That `consume` reaches `parsePayload`, and that `ExtractorOutput`'s abstract set is `track`/`endTracks`/`seekMap`, rest on existing test usage and memory.

## Tests and status

`FlvMetadataAdmissionTest` uses the actual default `FlvExtractor` and honours `RESULT_SEEK` by reopening the source:

- **Startup.**
  - Sniff: raw peek growth for a 128 KiB data offset, versus a guarded `false` before growth and a known-length EOF.
  - Unsniffed read: refused by the budget, or as malformed for an offset under 9.
- **SCRIPT declaration.** A raw 128 KiB native tag array is observed as the read target, versus guarded refusal before it, for both known and unknown length.
- **Real fixture.** Through `PlaybackExtractors`: AAC, 48 kHz, mono, with the same seek-map duration and sample count as the raw reader, then a reopen from 0.
- **Budgets.** Exact versus one-short slot budgets for strict-array, ECMA-map and object entries, and for depth, all checked by native decode of the duration. A raw `readAmfStrictArray` failure trace is the route witness.
- **Native ignores preserved.** Another name, a non-ECMA value, an empty value, an unknown AMF type, and scripts after the seek map are not refused.
- **Retry and reused buffer.**
  - An interrupted body retries unchanged and decodes; a changed retry is refused.
  - A reused-array case where native reads a stale double past its tag, which the guard refuses.
