## Finding / guard

Pinned Media3 1.11.0 `FlvExtractor` uses the header dataOffset for sniff lookahead, allocates a declared SCRIPT body before reading it, and passes onMetaData ECMA/strict arrays to count-sized native collections/recursive AMF parsing. These inspected files are unchanged in1.11.1. Extractor source SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`.

Public input/output hooks admit requested lookahead before growth, native startup offset/backing, SCRIPT declarations before allocation, and each physically delivered onMetaData body before native parse. Count/depth/backing and wide-position arithmetic are checked. Every retry is scanned again. Successful seek-map observation persists across seeks like native; later skipped scripts, ignored names/types and audio/video handling remain native. Cancellation happens before watched reads consume input. Root checked TagPayloadReader.consume and ExtractorOutput directly from the pinned source; no interface behavior relies on memory.

Proposed limits:16MiB requested lookahead,4MiB buffered SCRIPT,65,536 reserved AMF entries/capacities, depth16. The entry budget is not an exact HashMap bucket/reference/heap count. Unusually large valid metadata can be refused. Audio/video buffers, codec configuration, decoders, sample queues, old/new allocation overlap and whole heap are not certified.
