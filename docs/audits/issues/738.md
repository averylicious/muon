## Finding and route

Muon bounds incoming Tauon track records to16KiB, but native stream-derived values enter other fields. Pinned Media3 1.11.0 source shows:

- `AviExtractor.processStreamList` takes `StreamNameChunk.name` (the entire strn body) into `Format.label`. `Tracks.toBundle` → `TrackGroup.toBundle` → `Format.toBundle` serializes labels and codec `initializationData` directly.
- `TextInformationFrame.populateMediaMetadata` maps TCOM to composer. `MediaMetadata.toBundle` writes composer and other text as inline CharSequences. The bounded title/artist from Tauon does not set every optional stream-derived field.
- Muon's `PlaybackSessionCallback.externalCommands` includes GET_TRACKS/GET_METADATA for trusted external controllers. `MediaSessionStub.Controller2Cb.onPlayerInfoChanged` filters by available commands, then uses `PlayerInfo.toBundleForRemoteProcess` for another process. Track changes can send tracks without the repeated-update exclusion. The inspected dispatch catches RemoteException and logs it; this does not guarantee every oversized update reaches controls.

Thus this is an uncovered **transport payload budget**, distinct from parser preallocation and whole-process memory. An unusually large legitimate label, text field or codec initialization may be admitted by the proposed container budgets yet exceed a practical remote transaction budget. No specific remote failure or severity beyond that source risk has been reproduced.

## Qualified non-findings

- New controller interfaces use `BundleableByteArray` chunking for artwork. Legacy interfaces drop artwork over500,000bytes. Do not claim raw artwork automatically becomes one oversized transaction.
- `Format.toBundle` deliberately omits raw `Format.metadata`; APIC/Vorbis frame objects are not directly included through that field.
- In-process controllers use `toBundleInProcess` with a direct object reference. The app UI is not proof of a remote route failure.
