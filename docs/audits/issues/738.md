# #738: Remote metadata payload boundary

Updated 2026-10-28. Branch `codex/metadata-transport-audit-oct28` (draft #739), based on main `20579cf1`. Post-RC; frozen RC .1420 is unchanged. No phone, Binder transaction, crash or exploit has been demonstrated.

## Finding (source, pinned Media3 1.11.0)

Muon bounds Tauon track records to 16 KiB, but stream-derived values reach other session fields.

- **Labels and codec data.** An AVI `strn` body becomes `Format.label`. `Tracks` → `Format.toBundle` sends labels and codec `initializationData` inline.
- **Stream text.** `TextInformationFrame` maps TCOM to `composer`, and `MediaMetadata.toBundle` sends optional text inline.
- **Who receives it.** Remote controllers get both through `PlayerInfo.toBundleForRemoteProcess`. The legacy platform session converts composer, author, writer and description in `LegacyConversions.convertToMediaMetadataCompat`, then calls `setMetadata`.

This is a transport payload budget, separate from parser preallocation and whole-heap memory.

**Qualified non-findings:**
- Artwork is chunked for new controllers and dropped above 500,000 bytes for legacy ones.
- `Format.toBundle` omits raw `Format.metadata`.
- In-process controllers receive direct references.

**Characterization:** the two JVM cases in `MetadataTransportBoundaryTest` passed at `508965d3` / [.1568](https://github.com/averylicious/muon/actions/runs/40563835588). Under Robolectric, the serialized payloads exceed 1 MiB; no transaction is rejected. AVI fixture SHA256 `fa961f8cd5714d4b06c6c1beb0199a40057d9541b777a364dda1532cbfa6305a` (root-generated silence).

**First mitigation:** draft #712 (`e6151630`, .1571) removes `GET_TRACKS` from external and notification grants. It's included in #701.

## User decision (2026-10-28)

**Use bounded song metadata for controls.** Unused stream fields such as composer and description may be blank in controller metadata. Preserve playback, original file tags and the bounded title/artist.

## Implementation on this branch (first compile and tests PENDING)

**`ControlMetadataPlayer.kt`.** A `ForwardingSimpleBasePlayer` wraps the existing `PlaybackQueuePlayer` in the `MediaSession.Builder` (`PlaybackService.kt`).

- **Where it projects.** It overrides `getState()`: it takes `super.getState()`, then calls `buildUpon().setPlaylist(sameTimeline, sameTracks, projectedMetadata)`. `State.playlist` is never materialized.
- **Coverage.** Because `getState` serves both the initial getters and every update driven by `onEvents`, it covers:
  - initial and updated state;
  - listener events;
  - controller `PlayerInfo`;
  - the legacy stub, which reads `PlayerWrapper.getMediaMetadataWithCommandCheck()` from this player.
- **What the projection contains.** Taken from the current queued item in the timeline (an unset index means 0; an empty timeline gives `MediaMetadata.EMPTY`):
  - **Kept from the queued item:** title, artist, album and album artist. They replace the stream values, and a missing value stays blank.
  - **Cleared:** display title, subtitle, description, writer, author, composer, conductor, disc subtitle, genre, compilation and station.
  - **Set from the queued item:** artwork URI, extras and supported commands.
  - **Unchanged:** embedded artwork (the same array reference via `buildUpon`, so no copy) and numeric fields.

  It works from `raw.buildUpon()`, not `populate()`: pinned `populate` skips null fields and doesn't copy author.
- **Unchanged:**
  - the timeline and its window UIDs, and the native `Tracks` (labels and codec data);
  - timed metadata, positions, commands and every other event;
  - queue edits, which still reach the `PlaybackQueuePlayer` guards;
  - the raw ExoPlayer that ReplayGain and the queue-removal callback use.

**Tests (`ControlMetadataPlayerTest.kt`, Robolectric SDK 34, four methods):**
- **Hermetic.** Every real session uses a no-I/O `BitmapLoader`: `supportsMimeType` is false, and decode/load return failed futures. Tracks are never prepared, and Tauon items use a private-LAN endpoint with no network.
1. **Real `SimpleBasePlayer` producer.** Raw metadata has small, distinct values in every unused text field plus album artist, and only the composer is 2 MiB. It checks:
   - **Projection:**
     - queued title and artist kept;
     - an unknown album and album artist left blank;
     - every unused field cleared;
     - shared artwork and the track number kept.
   - **Raw side:** raw metadata and `Tracks` unchanged.
   - **Size:** the serialized projection under 16 KiB versus above 1 MiB raw.
   - **Updates:** no event when only unused text changes, an update to a new queued song, and the empty state.
2. **Real `MediaSession` with a `MediaController` and the public platform controller.** The platform controller is `android.media.session.MediaController(context, session.platformToken)`. Both are checked initially and after an update: title and artist present; composer, writer, author, description and genre absent.
3. **Real ExoPlayer inside `PlaybackQueuePlayer` inside the wrapper.**
   - Single-item and huge-list (`Int.MAX_VALUE`, non-iterable) set and add calls are refused, and the queue is kept.
   - Shuffle and repeat reach ExoPlayer, and releasing the wrapper releases it.
4. **The production stack plus `MediaSession` and the real `PlaybackSessionCallback(shufflePlayer = native)`.**
   - **Setup:** duplicate Tauon items with a fixed `QueueShuffleOrder` and shuffle on.
   - **Action:** the connected controller removes a duplicate that isn't playing (count 3), then Undo (count 4).
   - **Checks:** the original IDs and slot, and the exact native shuffled order, are restored.

All resources are released in `finally`. Existing characterization, queue, Undo and session tests are unchanged. CI is the first compile; nothing was run locally.

## Limits

- **Platform readback.** Test 2 reads the platform controller as Robolectric provides it. If Robolectric's shadows don't propagate session metadata, that assertion fails in CI and root diagnoses it. It is not a system_server, cross-process or OEM controller check either way.
- No Binder transaction, remote controller or device acceptance.
- The external `GET_TRACKS` restriction stays in #712/#701.
- No universal Binder or heap limit is claimed.
