## Finding and approved behavior

Pinned Media3 1.11.0 serializes optional stream composer/author/description into controller metadata; raw Tracks also carries labels/codec bytes. Modest synthetic public-Bundle characterization exceeds 1 MiB, without attempting a Binder transaction. The user approved **bounded queued-song metadata for controls**, leaving unused stream text blank. External GET_TRACKS exclusion is the separate #712 component, included in #701.

`ControlMetadataPlayer` wraps the existing `PlaybackQueuePlayer` only at the session boundary. Supported `ForwardingSimpleBasePlayer.getState` projects initial/getter/listener/modern-controller/legacy-conversion metadata: queued title, artist, album, album artist and references; unused text cleared. Unknown album stays blank. Original ExoPlayer Tracks/timed tags/ReplayGain and original files remain intact; embedded artwork shares its existing array and limits. Numeric fields remain. Queue mutations still reach their original guards.

A single cached public `ForwardingTimeline` view preserves UID/navigation/shuffle/Tracks and explicit projection across SimpleBasePlayer state copies. No playlist materialization, growing map or private production API. This is selected-song transport projection, not a universal Binder/heap limit.
