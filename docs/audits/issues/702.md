Updated 2026-10-25. [Owner issue](https://github.com/averylicious/muon/issues/702). Post-RC parser fix on `codex/replaygain-id3-tags-oct25`, based on main `dd8782a0426437093a99ea3f7205878b6af775bc`. Outside frozen M3E RC .1420 and combined candidate #701; no phone or music-file changes.

## Confirmed source gap

`ReplayGain.trackLoudness(Metadata)` accepted only `VorbisComment` with exactly upper-case keys. Pinned Media3 preserves Xiph key spelling and exposes MP3 ID3v2 user text as `TextInformationFrame`. rsgain writes ReplayGain gain/peak in ID3 TXXX frames and supports lowercase keys. A tagged MP3, or lowercase Xiph comment, therefore looks untagged to Muon and receives the existing library estimate/no-tag notice. This is a format-coverage gap, not a reproduced device regression or proof that the user's particular library contains affected files.

Source evidence: published Google Maven `media3-extractor:1.11.0` sources SHA256 `76404d34549e50b93f16c94119aace19dee06be9068c45a3d4f8ed5289e4eb3e`, `Id3Decoder.decodeTxxxFrame`, `TextInformationFrame`, `Mp3Extractor` track-format metadata and `VorbisComment` constructor. rsgain [pinned ID3 writer](https://github.com/complexlogic/rsgain/blob/aae8cc74190de9dafce41576f3e407e62420a51d/src/tag.cpp#L691). No library/API upgrade.

## Candidate behavior

Normalize supported comment keys with `Locale.ROOT`. Read scalar TXXX track gain/peak through the same existing finite/range/peak/no-amplification checks. Ignore unrelated frames, album gain, ambiguous multi-value fields and ID3 R128 (an Opus field). Existing Vorbis/R128 precedence, enabled setting, saved hints, storage and all persisted history remain. The bounded adapter retains only three relevant keys instead of copying all comments.

Three focused tests exercise actual pinned ID3 decoding from v2.3/v2.4 bytes, rejected/malformed/ambiguous frames, clipping protection and mixed-case Xiph/R128 precedence. Existing parsing and settings cases are retained. No local Android build; fresh CI is the first compile. Source inspection and decoder fixtures are not end-to-end sound verification.
