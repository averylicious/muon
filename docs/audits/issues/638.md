## Finding / implementation

A scan snapshots a LAN subnet, then sends queued requests through a shared unbound default client. Network handover can route old candidates through a different default and retain stale results. The original implementation in draft #643 (`12a45030073f7acc0a4e6917808e6e1df71d0ac0`) was source-reviewed and CI-tested but never merged. Its inherited CI/documentation stack is stale; the current branch ports only the six network/fixture files onto main `bfcaa4d293efa8f89c83f5ba53096a2d466f3227`, with a further displayed-owner guard. Do not merge the stale whole branch or claim its old CI validates this port.

Each round uses the selected default Network's socket factory and a private zero-idle pool, tracks its own calls and remains terminal after default/capability/subnet invalidation. It keeps one callback through NSD/probe completion, then unregisters on rescan/disposal/permission loss. Cancelling it does not cancel shared playback requests or stop the shared dispatcher/executor. Displayed rows and auto-connect capture the composing owner, so a replacement owner cannot authorize an old row/effect. IPv6-only LANs retain NSD even without IPv4 enumeration. Manual Connect remains unchanged; no process binding, underlying-VPN selection, new permissions or saved-address policy change.

Capabilities/callbacks are asynchronous. This reduces stale cross-network work and refuses cellular-reported/ambiguous automatic networks; it is **not a zero-cellular-packet guarantee** or a fix claim for unexplained #671 buffering.
