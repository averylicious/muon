# #645 — First-song loudness data and live toggle

Updated 2026-10-23. [Issue #645](https://github.com/averylicious/muon/issues/645), RC #636; implementation continues in [#648](https://github.com/averylicious/muon/pull/648). Verify its current head/checks before resuming.

## Verified cause

The reported first FLAC had **no ReplayGain tags**. Freshly cleared Diagnostic .1324 (source `af70c50c226cfafb5320052bf71950a40eef60a2`) shares the RC .1343 normalization code. Selected first-song testing on the POCO found:

- No gain preferences existed; ON/OFF changed `enabled`, but the same active AudioTrack's L/R gain stayed **0 dB**.
- After playing a tagged song, Muon remembered **−15.25 dB**. Returning to the untagged song used that library-median fallback at about **−15 dB**.
- With explicit user approval, rsgain added **−12.03 dB** track/album gain to that one source FLAC. Tags were backed up privately, decoded PCM hash stayed identical and file modification time was preserved. No re-encoding or whole-library rewrite.
- Another fresh Diagnostic reset then loaded the first song's own **−12.03 dB** gain. ON immediately changed the same active AudioTrack from **0 to about −12 dB**, and OFF immediately returned it to **0 dB**, without a track transition. Android's displayed dB values are rounded. This is pipeline evidence, not a subjective listening claim.

Only Diagnostic was cleared/played/toggled; regular Muon data and system volume/settings were preserved. Diagnostic was left paused with normalization off. Private dumps/addresses/IDs/file paths stay outside the repository.

## Implemented follow-up and acceptance

User requested an in-app reminder for future songs they forget to tag, with Opus 5.5 UI/UX input. Current changes publish only the current selected-audio status, distinguish checking/no data/tagged/estimated, and prevent ineffective enabling until a usable gain exists. An already-enabled setting can always be disabled. A concise Material3 Snackbar says **“No ReplayGain tags for this song.”**, with **Details** explaining computer-side tagging and fallback behavior. It overlays the player without resizing artwork and never interrupts audio.

Reminder suppression retains at most 64 recent song IDs, not an ever-growing per-song preference index. It only considers actually playing selected audio, not buffering/empty track lists. The reminder also works with normalization off, matching the user's explicit request to catch forgotten tagging. Repeated songs within that recent window are suppressed; beyond it, a reminder can recur. No new dependency, music-file scan, automatic tagging or gain boost.
