## Separate confirmed error-classification defect / current fix

Main's legacy Delete branch maps any census open/read/close failure to `NotOwned`; its warning therefore cannot distinguish failed storage reads from unsafe ownership. `Unavailable` also always mentions SD even for phone storage.

The new production helper `OfflineStore.legacyRemovalRefusal` returns `Unavailable` for a failed complete census; missing/mismatched/shared/unsupported rows remain `NotOwned`. Sole ownership alone admits the unchanged removal-delivery path. Unavailable notices now identify SD only for card copies and suggest checking/retrying storage. No paths, server details or raw exceptions appear.

Two focused additions to existing `IndexNameProbeTest` use native SQLite and controlled cursor failures: valid ownership admitted; hidden aliases/missing/rekeyed/stale keys refused; open/read/close failures unavailable with cursor cleanup and intact rows; a healthy retry admitted. They exercise actual production admission, not the whole Store/service deletion path. No cache/manager is passed to the helper, and no new deletion authority is granted.
