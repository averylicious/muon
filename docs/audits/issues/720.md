Updated2026-10-27. [Owner issue](https://github.com/averylicious/muon/issues/720). Main20579cf1 / Media3 1.11.0, also applicable to inspected alphaEE. Separate post-RC maintenance, **not a frozen .1420 gate**. No phones or user media; no reproduced OOM/crash/exploit or #671 diagnosis.

## Confirmed source boundaries

- Ordinary `Mp4Extractor` allocates parsed leaf buffers before body/file/parent bounds, retains moov leaves, and builds normal/rechunk/edit/accumulated tables from metadata declarations. Compact fixed-size tables can amplify their declared counts. Metadata is bounded separately from mdat/audio.
- Shared `Sniffer` can expand its search at moov/uuid, grow a peek buffer on skipped metadata and allocate ftyp before its body peek. Both factory MP4 candidates reach it.
- Fragmented `parseTruns` sums counts before `TrackFragment.initTables` allocates four arrays with25% headroom; tfhd/trex defaults permit no per-sample trun payload. Parsed leaf and PSSH key-count paths also need admission.
- **The default factory enables MFRA seek-map reading**, unlike the bare fragmented constructor. Its tail route checks integer/file ranges but can still allocate the claimed mfra suffix before its full body read. Tfra backing checks bound later tables to that suffix; this is not an unrestricted-count finding for tfra.

## Production behavior / remaining work

[Guard design and source-review corrections](../2026-10-27-mp4-admission.md). Parsed-leaf, parent/file/overflow, depth/count and shared table admission are wired to actual ordinary reads; both sniff paths are guarded. Ambiguous fixed formats admit **both** normal and chunk-based costs. The first implementation's normal-only fallback was unsafe for possible PCM and was corrected before push. Simple proven raw entries retain efficient rechunk admission.

User provisionally accepted the weighted-row limit on2026-10-27 with clear long-file documentation. Other limits/compatibility still need ordinary acceptance. Defaults:32MiB metadata/peek,1,048,576 weighted table rows,16MiB declared sample,64KiB ftyp,4,096 parsed boxes and depth16. Long AAC around2–3hours and ambiguous PCM may be refused. No whole-file or universal heap/decoder guarantee.

**Next:** verify the newly staged separate #701 combination and later resource-policy/runtime acceptance. The planned guard source is implemented at FCCA: ordinary/nested/sniff, first/repeated fragmented movie and leaf/PSSH, backed/summed truns, persistent per-track table/encryption peaks, deduplicated sidx/merged copies, MFRA and selected tfhd/trex sizes. Explicit sample sizes override unused defaults; first-mvex and sole-default ID behavior match pinned source. Future whitelist/state drift refuses instead of silently disabling observation. No phone requested this cycle; integration stays uninstalled/draft.
