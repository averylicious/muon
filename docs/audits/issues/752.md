# Stable Media3 patch — #752

Updated2026-10-28. Main-track post-RC proposal; frozen M3E RC .1420 and installed apps stay unchanged.

## Finding and scope

Muon pins Media3 1.11.0. The published 1.11.1 patch changes DefaultAudioSink's pending-release query to the AudioOutputProvider. AudioTrackAudioOutput's release executor decrements its synchronized counter even when its listener's playback handler has stopped. The old sink-local count depended on that listener callback. [Upstream #3338](https://github.com/androidx/media/issues/3338), [official release notes](https://developer.android.com/jetpack/androidx/releases/media3#1.11.1).

Update only the three explicit Media3 dependencies in app/build.gradle.kts together. Activity/Compose, packages, signing, saved bytes and release behavior are unchanged. No custom audio sink/provider is used. This is an upstream lifecycle correction, **not a reproduction, diagnosis or resolution of Muon #671**.

Selected compatibility assessment:
- Session legacy-browser connection now handles asynchronous root callbacks without the old handler wait. Muon's immediate-future root path does not establish that specific deadlock here.
- Known-length truncated ID3 tags are skipped before their advertised array allocation; unknown-length input still needs the app's admission policy. The combined suite's old known-short-length allocation witness must be replaced with **both** the fixed negative control and an unknown-length positive control, not deleted or weakened.
- FixedSampleSizeRechunker now uses at least one sample per buffer. The app's MP4 admission already uses maxOf(1,8192/frame) and an upper bound for uncertain raw formats; recheck against the combined native tests.
- HAGC configuration moves at unstable APIs. Muon calls none of the removed setters. Parser guard identity/order, subtitle policy and factory retention still require the combined compile/native suite.
- Matroska late-Tracks seek-map preparation and progressive track discarding changed. Do not equate passing ordinary fixtures with every mixed/live file or real audio output.
- Existing shipped Baseline Profile input is retained; no new profile capture or performance benefit is claimed.
