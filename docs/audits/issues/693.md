## Finding / scope

Main's Gradle8.13 and experimental `ee7ddb75`'s Gradle9.6.0 match the affected version ranges in three October7 maintainer advisories: [TLS fallback](https://github.com/gradle/gradle/security/advisories/GHSA-j5m7-59rp-24f5), [worker/daemon channel](https://github.com/gradle/gradle/security/advisories/GHSA-mvvg-497x-hmj8), and [client/daemon channel](https://github.com/gradle/gradle/security/advisories/GHSA-xwqc-3h47-hg64). Their open-source patched lines are8.14.6 and9.8.1. Main's8.13 also predates the January repository-failure fixes covered by8.14.6.

Repository fallthrough requires an attacker-controlled later source and failure of an earlier one. The daemon issues involve a co-located attacker and local communication; they are not Android media-player vulnerabilities or evidence of an Internet-exposed daemon. No compromise was demonstrated. Single-tenant hosted CI reduces the local-host threat but does not replace the patch. `--no-daemon` is not used as an exemption.

## Main implementation and provenance

Update only main's Gradle distribution to8.14.6, its official released wrapper JAR and exact wrapper/properties pins. Keep AGP, Kotlin, Compose, repositories, launcher scripts, package/signing identities, cache quarantine and CI check ordering unchanged. The existing launchers call the same wrapper entry point; CI is the first execution/build verification of this combination.

Official sources: [8.14.6 release notes](https://docs.gradle.org/8.14.6/release-notes.html), [distribution checksum](https://services.gradle.org/distributions/gradle-8.14.6-bin.zip.sha256), [wrapper checksum](https://services.gradle.org/distributions/gradle-8.14.6-wrapper.jar.sha256). The downloaded release ZIP matched `7988ed071b2a07900e2ec715fca15c6ab72bce6db433af301fa7fa7e9407bd24`. Its nested `gradle-wrapper-main` payload's generated wrapper matched `ad16bca46cb71bb5887c546860d93992aeee35c1fdaf4a242b0a612375d937e0` before copying. The Gradle repository tag's own bootstrap wrapper instead targets8.14.3, so that different JAR was not used or executed. No checksum gate was relaxed.

This verifies these release bytes against Gradle's published HTTPS checksums, not an independent signing-key chain for every dependency/tool. Broader publisher/dependency verification stays under the user's existing deferral. Repository Dependabot-alert access reports disabled/403; no auth scope or repository security setting changed. Filtered public advisory queries did not establish coverage; direct maintainer advisories are the evidence.
