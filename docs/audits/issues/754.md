## Muon reachability — qualified

The app does not directly use ObjectInputStream or Serializable storage. That alone does not clear Android's Intent/Bundle boundary.

On AOSP android-9.0.0_r61/API28 (Muon supports28+), MainActivity is exported; StorageReviewEntry.accepts reads its string extra after finding a persisted capability but before comparing the supplied one. BaseBundle.getString unparcels its map before the String cast. Parcel.readArrayMapInternal reads every value, and VAL_SERIALIZABLE calls an ObjectInputStream with the app loader supplied by ActivityThread. Thus an unrelated serialized value can be reached before that capability comparison in this source route. Catching RuntimeException does not bound allocation. This is **source reachability**, not an executed Binder/phone exploit; other Android/OEM versions are not inferred from API28.

The actual .1644 release R8 mapping/usage reports remove CompactHashSet/MapMakerInternalMap and CompactHashMap's private serialization methods. That narrows exposure for **that inspected release APK**, not all APKs/frozen RCs. Canary does not enable shrinking; actual .1644 APK inspection confirms CompactHashSet.readObject still passes the supplied count directly to init. Actual patched .1647 Canary bytecode instead calls Math.min(count,256) before init. Static packaged-code inspection is not an executed deserialization/Binder test. Do not label the whole app remotely exploitable from a package-version match. No crash/OOM payload or phone test is run.

AOSP source links: [BaseBundle](https://android.googlesource.com/platform/frameworks/base/+/android-9.0.0_r61/core/java/android/os/BaseBundle.java), [Parcel](https://android.googlesource.com/platform/frameworks/base/+/android-9.0.0_r61/core/java/android/os/Parcel.java), [ActivityThread](https://android.googlesource.com/platform/frameworks/base/+/android-9.0.0_r61/core/java/android/app/ActivityThread.java).
