## Confirmed finding and questions

1. **Confirmed on the shipped recorder; fix drafted, uncompiled and unrun.** The recorder in the frozen RC and main `bfcaa4d2` can report success without completing its journeys. It returns normally when Pause never appears and skips player/Queue without the collapse control. `tap`, `openFirst` and `scroll` do nothing on absent targets, and only the initial Songs wait is asserted. The recorder-hardening slice (`codex/profile-recorder-validation-oct24`, prepared for CI) changes `BaselineProfileGenerator.kt` so that every step waits for its destination and throws a timed message naming it:
   - the view buttons and a list;
   - album and artist page arrival (`Back to albums` / `Back to artists`) and return to the library;
   - Pause after starting a song, then Now Playing (`Collapse the player`);
   - Queue arrival (`Back to Now Playing`) and return;
   - the pause taking effect, and Now Playing closing.

   On failure it attempts one Pause in the `dev.avery.muon.benchmark` package and attaches any cleanup error as suppressed, so the original failure is still reported.
2. **Partly addressed; needs device confirmation.** Rows are still chosen by position: there is no stable selector, because `onClickLabel` ("Open album"/"Open artist") is not a content description, and song rows have none. The heuristic is now narrower: the topmost enabled clickable, at least 5% of display height, inside the largest scrollable, skipping `Order:` buttons. The largest-scrollable rule avoids the horizontally scrolling chip row, and the `Order:` rule covers M3E's in-grid sort pill. A wrong tap now fails at the destination check instead of recording silently. Whether it picks a library entry rather than, say, an M3E Jump back in tile, is unverified. Queue tries the landscape icon description first, then the portrait text button. A portrait Now Playing that scrolls (short window, large font, error card) may leave Queue off screen; that fails clearly but is not handled.
3. **Coverage boundaries (unchanged):** the manual profile receipt predates M3E. This means current M3E journeys have not been revalidated, **not** that every Expressive method is absent: common methods and merged dependency profiles may already cover some paths. Generator supports API33+; current recorded API37 flow does not establish older-platform branches. Existing journeys do not seed saved/SD/offline states. Preserve the Benchmark package/storage gate; do not expand into storage stress just to improve a profile.

Local-network grant in the slice:
- It now runs once before `collect`, and only when `SDK_INT >= 37`, matching the app's `LOCAL_NETWORK_API`. API 33–36 skip it.
- `UiDevice.executeShellCommand` returns only standard output, so a refusal by `pm` would not show up there. Instead the slice reads `dumpsys package` back and requires `ACCESS_LOCAL_NETWORK: granted=true`, failing clearly otherwise. That output format is assumed, not checked on a device.

No network/firewall or installed-app setting change was made.
