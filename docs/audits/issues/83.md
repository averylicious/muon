A missing target fails with a timed message instead of silently succeeding. Failure cleanup attempts Pause only in Benchmark, preserving the original error.

- Selectors are package-scoped. Entry selection remains positional: enabled clickables at least 40 dp high within the largest scrollable, excluding `Order:` controls. Wrong destinations now fail; actual tile selection still needs traversal testing.
- Queue supports the landscape icon and portrait text button. A below-fold Queue control now gets at most four upward content swipes scoped to Benchmark's visible default-display window, with foreground checks; remaining failure is explicit. Physical short-window/large-font traversal is still pending.
- On API 37+, grant local-network access once before collection and verify this instrumentation user's permission through PackageManager. The compiled self-instrumenting helper already inherits `QUERY_ALL_PACKAGES` from its test dependencies, so the target is visible; no extra query or permission was added. Earlier supported APIs skip that grant.
- Keep Benchmark's separate package and storage gate. Do not use the installed frozen RC, expand this into saved/SD stress, or accept stale exported files as a new successful recording.

## Prepared first-frame measurement

An opt-in **measurement** dispatch builds the same separate Benchmark package with release minification/resource shrinking and the shipped profile; ordinary recording builds remain unminified. Both helpers/targets declare and check their mode, preventing accidental profile recording from an obfuscated measurement target. No release package ID, signing path or published APK changes.

`StartupBenchmark` compares ten cold first-frame iterations on the same APK under `None()` versus `Partial(Require, warmupIterations=0)`. API37+ device/target and denied Benchmark LAN permission keep the fresh Connect journey independent of changing Tauon/discovery responses. It explicitly requires permission via a reset argument to clear **only Benchmark data before compilation**, then verifies the destination. It does not measure loaded-library readiness, playback or scrolling; OS/filesystem caches are not flushed. Counterbalanced batches and thermal/configuration review remain required. [Protocol](../../baseline-profile.md#matched-first-frame-experiment).

Initial measurement head `a320e4aa` compiled successfully in recording tools .30 and minified tools .31, with exactly two passing storage-gate cases each. Actual manifests/profile assets confirmed the two modes and non-debuggable/profileable target. Artifact inspection then found that the helper, unlike the app target, used a runner-generated default signing key. A new pair gate reproduced rejection of that downloaded helper. The helper now uses the existing pinned debug key, with mode/package/self-instrumentation verification before upload; 133 local CI-policy regressions pass. This changes the formerly ephemeral tool identity, not Stable/Canary signing. Old helpers may need a consented tool-only reinstall after preserving results.

Final-head recording/measurement builds and runtime results are pending. The prior recorder-only CI receipts above do not validate this new implementation. No profile was regenerated or installed.
