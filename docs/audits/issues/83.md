## Confirmed finding and questions

1. **Confirmed: recorder success does not establish completed journeys.** `BaselineProfileGenerator.generate()` returns normally from its collect block when Pause never appears (line44); it conditionally skips player/Queue if the collapse control is absent. `tap`, `openFirst` and `scroll` quietly do nothing on absent targets. Only initial Songs visibility is asserted. A valid output file can therefore represent a partial journey.
2. **Needs device confirmation: current UI selectors are too broad.** `openFirst()` chooses a clickable node below 40% screen height, which could be a sort/recent/navigation control. Missing-target failure is confirmed; a wrong click on current M3E is a hypothesis. Prefer semantic row actions and require the reached page/back label. Portrait Queue still has visible text; landscape uses an icon description, so do not claim the text selector is universally broken.
3. **Coverage boundaries:** the manual profile receipt predates M3E. This means current M3E journeys have not been revalidated, **not** that every Expressive method is absent: common methods and merged dependency profiles may already cover some paths. Generator supports API33+; current recorded API37 flow does not establish older-platform branches. Existing journeys do not seed saved/SD/offline states. Preserve the Benchmark package/storage gate; do not expand into storage stress just to improve a profile.

The unconditional local-network `pm grant` output is ignored. Guard it by platform capability and fail clearly on a real grant failure when hardening the recorder; older APIs do not need this permission. No network/firewall or installed-app setting change was made.
