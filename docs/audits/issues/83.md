## Current implementation

Recorder journeys now require their actual destination/play/pause/return state instead of silently skipping missing controls. Package-scoped selectors, at-least40dp rows, permission-user checks and Benchmark-only cleanup remain. Entry selection is positional and below-fold controls can still fail; physical traversal is not proven by compilation.

A separate opt-in **measurement** tools build creates a minified/profileable/non-debuggable Benchmark target, with a matched helper and an explicit mode marker. Normal recording remains unminified. Two Macrobenchmark cases compare one measurement APK using `None` versus `Partial(Require, warmups=0)`, ten cold **first Connect-frame** iterations each. They do not measure library-ready, playback or scrolling; those broader journeys remain engineering/measurement work after the controlled pilot. Existing APK profile rules are not replaced.

The harness requires API37+ both on device and target app, user0, denied Benchmark LAN permission, the right mode, and explicit `muonAllowBenchmarkDataReset=true`. It clears **only Benchmark** before compilation, checks the intended first screen, and stops only that target if armed. [Proposed protocol and limitations](https://github.com/averylicious/muon/blob/codex/profile-recorder-validation-oct24/docs/baseline-profile.md). Historical device permission does not authorize running it now.

Both tool APKs now use the repository's pinned debug signer. The older helper used an ephemeral runner key; do not silently uninstall a mismatched installed helper. A pre-upload gate checks exact APK pair, signers, target identity/non-debuggable/profileable mode, and self-instrumenting helper. Existing Android runtime identities and signing keys are unchanged.
