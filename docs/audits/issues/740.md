# #740: Discard unused strict tracklist JSON graphs

Updated 2026-10-28. Post-RC source and engineering task on `codex/tracklist-discard-oct28`, from main `20579cf1a056b9c4a095aa860355f624877122de`. Root assessed the source first. No new frozen-RC gate.

## Problem

`strictTracklist` built and then discarded a `JSONObject`/`JSONArray` graph for every unknown root value. `readTrackJsonValue` also kept every unknown per-record field, although `projectTauonTrack` reads only these fields:

- `id`, `title`, `path`, `artist`, `album`
- `duration`, `can_download`, `has_lyrics`
- `album_artist`, `track_number`

Records after the first deferred projection failure, and non-object records, were built too.

## Change (`TauonTracklist.kt`)

`readTrackJsonValue` gains `retain`/`record` flags on the existing walk; there is no new parser.

- **Discarded values.** With `retain=false`, every value is still read by the strict `JsonReader`, syntax-checked and checkpointed exactly as before (one checkpoint per value). No container is built.
- **Retained records.** A retained track record keeps only the fields above. A retained known value keeps its complete nested shape, so the existing `optString`/`opt` coercions are unchanged. The field filter is not applied recursively.
- **Not built at all:**
  - outer extensions;
  - a non-array `tracks` value;
  - non-object records;
  - records after a deferred failure in the same `tracks` array.
- **Numeric parent parity**, from AOSP android-14.0.0_r1:
  - `JSONTokener.readObject` uses `JSONObject.put`, which rejects a non-finite `Number`;
  - `readArray` uses `JSONArray.put(Object)`, which does not.

  A private `requireObjectMember` keeps the object rule for discarded members, and also for root members, which had escaped it on the strict path. A root-level or wrong-type `tracks` scalar such as `1e999` now fails as the full `JSONObject` does. Array primitives are still accepted.
- **Unchanged:**
  - numeric conversion stays `JSONTokener(nextString).nextValue()`;
  - preflight depth, value and array limits still run first;
  - cancellation ordering;
  - deferred projection errors with last-`tracks`-wins;
  - syntax and value failures still abort;
  - known-field coercions and the title fallback;
  - the lenient bounded-DOM fallback.

## Tests (`TauonTracklistTest.kt`, Robolectric SDK 28/34)

- **Extended cancellation control.** A small strict input with discarded outer trees, unused record fields and records after a failure is cancelled at every visited boundary. The visited count comes from the successful parse, so it is not quadratic on large input.
- **New: discarded trees project like the full object.**
  - Known nested object/array values for `artist`, `album`, `track_number` and `album_artist`.
  - A duplicate `id` within a record.
  - Records after a failure, including an array primitive `1e999`.
  - Wrong-type and then valid `tracks`.
- **New: non-finite parent parity.** Root, overridden-`tracks`, unknown-field, discarded-record, nested-ignored and known-nested object members reject with `JSONException`, like the previous full parse. Array primitives are accepted and match.

The existing structural-limit, coercion, lenient, duplicate and malformed cases are unchanged.

## Limits

- Strings and number literals are still read transiently, the raw response stays wire-bounded, and the projected tracks and the lenient fallback keep their existing bounds.
- No heap reduction, speed-up, OOM or exploit is measured or claimed.
- No new dependencies, caps, schema, coercions or caller changes.
