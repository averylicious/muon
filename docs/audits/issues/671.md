# #671 — intermittent streaming buffering

Updated 2026-10-24. Owner: [#671](https://github.com/averylicious/muon/issues/671). Track: M3E, audit baseline `1ba260fb01151a3a4cd4e0810a20cfe9f3352c74`.

## Finding

The user observed prolonged buffering on the POCO with Canary .1395; playback later recovered. The retained log started too late to establish a cause. A loaded library/reachable Tauon does not prove an audio request stayed healthy. Router, host, ROM and app explanations remain unverified; no reboot or network reconfiguration is required by this investigation.

## Candidate and evidence

This branch adds a passive `MuonPlayback` observer to the **separate debuggable Diagnostic package only**. Canary, Stable and Benchmark do not attach it. It records fixed numeric/enum player states, loading/position/buffer observations, broad network transport, and source-load start/completion/cancel/error events. No URLs, media IDs, song metadata, headers, exception messages or persistent report files are emitted. It changes no retry, buffering, network, volume or playback policy.

Samples occur every five seconds while the player wants to play and is buffering. A 1,024-line service-lifetime budget bounds output and stops sampling when exhausted; the final line marks the cap. Closing the service detaches the listener and timer. Logs are local logcat and may roll over; this is not an always-on incident recorder.

Media3 APIs checked against Google's Maven `media3-exoplayer:1.11.0` sources (`AnalyticsListener.java`, `LoadEventInfo.java`), including the retry-count overload. CI is the first Android compile; exact candidate/run will be recorded on the PR. New tests exercise the build/package gate, log budget, error classification and real-listener metadata exclusion/detachment. Device capture and recurrence remain unverified.

## Next action

Build with the existing manual `diagnostic_debug=true` workflow input. Use Muon diag for a listening session when convenient; preserve regular Canary and Stable. Start a filtered local capture **before** reproducing:

```sh
adb -s <current-POCO-serial> logcat -v monotonic -s MuonPlayback:D '*:S' > muon-buffering-local.txt
```

Record whether the user intended playback and approximately when buffering began/recovered. State numbers: 1 idle, 2 buffering, 3 ready, 4 ended. `wanted` is play intent; `playing` is actual playback; `suppression` distinguishes a player suppression; `loading` and repeated samples show whether the loader/buffer is changing. Error categories are clues, not proof of a router/phone defect. This observer does not expose internal LoadControl decisions or audio-server processing time.

Do not upload raw device logs to this public repository. Review and summarize only relevant sanitized observations. Keep the issue open until evidence supports a cause and a separately verified fix or explicit release disposition.
