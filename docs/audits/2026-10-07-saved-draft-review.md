## Startup preservation follow-up (source, first CI pending)

Pinned Media3 `DownloadManager.initialize` resets downloading states and then snapshots queued/stopped/downloading/removing/restarting rows before syncing tasks. Its `onRemoveTaskStopped` removes the index row even when a downloader threw. Pausing downloads alone never stops a removing/restarting task.

The production shelf now wraps the supported `WritableDownloadIndex` with `RetainedDownloadIndex`. Its first initialization or inventory query, serialized on the decorator, pauses every retained queued/downloading/removing/restarting operation as STOPPED with a distinct stop reason, preserving request, times, length and progress. Completed/failed/already-stopped rows are untouched. No cache bytes, identities or cover files are rewritten. Failure to read/update propagates to Media3 initialization, which starts no tasks. Bootstrap/inventory queries use the same gate so they cannot first publish pre-preservation task states.

This deliberately changes restart behavior: unfinished saves are kept paused instead of automatically extending old partial bytes from a possibly reused server address; pending deletions are retained instead of resumed. The user can save a fresh copy from the live library or explicitly remove a sole-owner retained copy. A fully cached paused entry remains locally playable and Unverified. Partial entries say that a new copy must be saved; retained aliases remain non-removable. No automatic resume action is exposed. Current-process new saves/removals still delegate normally.

Six real-manager/native-index/cache controls cover the actual unguarded shared-key deletion, index loss despite a throwing remover, guarded startup, read failure, queued/downloading/restarting preservation across another manager restart, and subsequent fresh addition/intentional sole-owner removal. Their first compile/run is pending. They do not test Android service delivery, physical storage loss, successful codec decoding, or device UI. The startup path is not claimed fixed until exact-head CI and review; full #179 recovery remains deferred.
