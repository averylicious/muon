## Suggested bounded sequence

1. **New-save allocation owner**, with real native/SQLite restart/freshness/unknown-UID/original-preservation controls. No UI or production switch yet.
2. **Backend routing**, including disk inventory/membership, saved readers, downloader/played paths, request/record/cover ownership and pre-manager destructive exclusion. Test the real manager record-deletion failure path and ordinary writer/reader cancellation.
3. **Opt-in migration owner/worker**, with an explicit admission barrier, bounded per-item work/progress/cancel/deadline, free-space checks and atomic verified routing. Preserve legacy availability and show unsupported/incomplete progress truthfully. A retry uses a distinct fresh-attempt adapter; a partial old target is never adopted.
4. **Opt-in controls and recovery integration**, including restart at Copying/Verified/Ready and failures before/after handover, plus disabled/default-mode behavior. Successful migration does not itself authorize deleting legacy originals.
5. **Device acceptance**, after controlled production tests pass. Confirm current-task POCO rooted-ADB authorization then for disposable private records/card identity, cancel/restart and byte preservation. Keep hardware and TalkBack spoken/focus UAT distinct from automated/source evidence.

The public legacy Cache API still opens its full index before per-resource extraction. The current migration helper therefore has a high possible transition peak. Do not claim it solves initial legacy startup OOM. OPEN#459/#460 now prepare a bounded pinned-format read-only transition with actual preservation controls; production must select it without first opening SimpleCache, and unsupported originals must refuse intact with truthful feedback. Measure/explicitly disposition this transition before calling the redesign complete. #401 now has a source-correlated Ogg tiny-read bottleneck and a controlled diagnostic read-ahead comparison (39.115s to0.881s first selection), with two audio hashes and two saved rows preserved. That limited fixture result does not establish large-library bounds, ordinary release behavior or general card recovery; normal acceptance remains pending.
