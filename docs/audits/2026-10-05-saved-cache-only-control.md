# Saved playback: cache-only mechanism control

Inspected main `75c6a99454d8598dce3225aa5dc513d8b78b8b5f`. Test-only continuation of [#213's chosen policy](2026-10-05-retained-identity-policy-map.md): live selection streams, uncertain retained copies remain separately reachable Unverified, and missing saved bytes must not fetch a reused live ID. GPT-6 / Codex desktop, effort not reported; author self-review. No production route/schema/controller change, network requests, phone access, user-cache operation or independent review.

`SavedCacheOnlyControlTest` exercises actual Media3 CacheDataSource/SimpleCache with native SQLite and disposable byte spans. A private factory has **null upstream** and **null write sink**. Three cases check the mechanism: an exact opaque key reads cached A despite a different nominal live URI; an absent key raises IOException rather than using that URI/another cached entry; a partial A prefix reads but its gap raises IOException and stays unfilled. Existing saved span bytes are checked after closing. These are byte fixtures, not audio decoding or a implemented saved UI/route.

Pinned published Google Maven datasource sources SHA-256 `a54ddd9858ed2de57e07c5461dcebdae7a53d92a60210a2a3f5bf501398a5e4a` were read: `CacheDataSource.Factory.setUpstreamDataSourceFactory` documents null as cache-miss failure; `createDataSourceInternal` disables writes for null upstream; the constructor substitutes PlaceholderDataSource; `openNextSource` selects a cached file or that placeholder on a hole. No custom mock upstream/throwing data source supplies the expected failure.

This provides the library mechanism needed by a **future coherent app boundary**. Current `Shelf.source` still has an OkHttp upstream, and `OfflineDataSource` uses it; these controls do not fix that route or claim it already rejects missing saved bytes. Cached coverage and a matching key are not content identity. The nominal URI is not a safe capability: final production selection must carry validated local entry/shelf provenance, stay on the same admitted generation, never reconstruct a saved selection as a live URL during queue Undo, and preserve the restricted external-controller entry gate.

The fixture uses NoOpCacheEvictor, a healthy preinitialized disposable cache and single-threaded requests. It does not characterize played-copy eviction/touching, concurrent deletion/removal, adaptive streams, filesystem durability, card lifecycle, MediaItem/Binder transport, service callbacks, app-visible error handling or retries. No network source exists in this fixture; no end-to-end instrumentation of an application retry path is claimed. #179/#230/#253 and pending #248/#302 integration remain separate constraints. No cache release/adoption/migration is authorized by a successful read.

CI is the first Kotlin compile/execution; exact head/run, XML counts and artifacts are recorded on the PR.
