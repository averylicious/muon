# Cache-only completed reads use read-only content metadata

Cumulative #614 a889b2879ce3f87a390c8633890fa7b07870682b; audit #401/#253. GPT-6 / Codex desktop, exact variant/effort not reported; implementation/source self-check, no independent review or Claude contribution.

`PartitionCompletedAudio` previously used the ordinary read/write sidecar factory even though its completed/played readers have neither an upstream nor a cache-write sink. It now uses a dedicated `openClosedSavePlayback` factory, retaining the exact Closed route/allocation/native UID checks but opening the content-metadata sidecar transactionally read-only on API35+. Older platforms keep the previous supported writable transaction path. This is the existing bounded sidecar mode, not a replacement for Media3's native database. Native span touches remain enabled for playback/LRU; native database ownership/release, ordinary factories used by mutations, fresh route/complete-row checks, corruption refusal, actual close/quarantine and residency guards are unchanged. No metadata cache or omitted validation.

Source basis: [API35 SQLiteDatabase](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/database/sqlite/SQLiteDatabase.java) and pinned [Media3 datasource1.11.0 sources](https://dl.google.com/dl/android/maven2/androidx/media3/media3-datasource/1.11.0/media3-datasource-1.11.0-sources.jar), SHA256 a54ddd9858ed2de57e07c5461dcebdae7a53d92a60210a2a3f5bf501398a5e4a. CacheDataSource applies content metadata mutations only when writing to cache. Actual `savedCacheReader` has null upstream and null write sink; it still checks actual FileDataSource close. Android17 framework implementation not independently inspected.

Existing composed API34/35 control now exercises both cache-only factories with full audio digest and chunked unknown metadata, checking actual read-only mode, unchanged sidecar/journal and zero residency after close. It still proves the ordinary factory can update metadata. The existing real DownloadManager completion/restart/read/close control now also runs on API35, through the actual changed `PartitionCompletedAudio` source. No new test class, dependency or storage format. CI remains the first Android compile/run.
