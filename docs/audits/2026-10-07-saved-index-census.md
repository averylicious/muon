# Saved inventory: release raw rows after projection

Continuation of #253 on the #373 acceptance stack, including current main e1e723fc3ba862ffe10626cd732c8af0c38d775a. GPT-6 / Codex desktop, exact variant/effort not reported: implementation and source self-review, not independent review.

`OfflineStore.savedEntries` previously called `rows(shelf)` and retained all Download objects, including legacy raw metadata byte arrays, while constructing a second list of saved display entries. It now uses one rewindable DownloadIndex cursor: the first pass retains only ID/key counts and eligible names; the second projects one row at a time. Every state and even an unrepresentable/hidden row participates in ownership. Saturated counts stop at two: enough to refuse sole ownership without counter overflow. No audio/index mutation, truncation, skipped saved entries or new hard library limit.

The cursor closes after success or an exception. Destructive removal still rechecks the current complete index through its existing admission path; the census remains a snapshot, not atomic writer exclusion. Two native-SQLite/SimpleCache controls establish one query/two passes, hidden aliases protecting a displayed entry, cursor closure, and failure preserving rows/audio. Existing list-based controls retain duplicate-ID/linear-census and predecode coverage. API checked in pinned Media3 exoplayer1.11.0 published DownloadCursor and DownloadIndex sources: Closeable cursor with moveToPosition(-1), state-less getDownloads returns all states.
