## User-selected behavior

On October 5 the user chose [#213's uncertain-record policy](https://github.com/averylicious/muon/issues/213#issuecomment-5989192715): **stream the live entry; show the saved copy separately as unverified**. Retain its bytes and saved metadata, make it reachable offline, and visibly label Unverified without relying on color. This includes older records for which identical tags/origin/numeric ID do not establish audio equivalence. A live entry must not inherit the saved copy's download badge, artwork or destructive actions merely from the shared numeric ID. This is behavior approval, not permission for destructive migration or releasing an uncertain removable cache.

[Installed Tauon source](2026-10-05-tauon-retained-identity-source.md) provides tags/path and allocation IDs, not a verified content identity. The running server was not queried. Tags/path hashes are hints, not audio verification or anonymization; neither matching tags nor a new client record format by itself makes a copy Verified. Stronger server identity remains an investigation. All application PRs remain open for manual acceptance.

| Playback | `PlaybackService.kt`: `TauonTrack.mediaItem` uses the live URL/mediaId and transports saved tags in SONG_EXTRA. `OfflineRoute.kt`: `routeOfflineRequest` selects an explicit completed ID before considering offline mode. `OfflineDataSource.kt` creates the selected shelf's cache source. | Current progressive DataSpec carries no independent retained-entry handle. Weak matching cannot fix the route; saved playback needs a distinct request provenance and cache-only behavior. |
| Recent copies | `OfflineStore.copyPlayed`, `playedCopy` and `OfflineRoute.hasPlayedCopy` use the same numeric ID; complete explicit/played records suppress later copying. | Account for opportunistic copies, not just the download manager's index. No overwritten retained bytes to make a reused ID appear current. |
| Saved listing | `OfflineStore.downloadedSongs` converts saved records to TauonTrack and deduplicates played copies by numeric ID. `downloadedLibrary` selects an origin; `LibraryModel.showOffline` uses a global offline mode and the ordinary library track model. | A separate saved-entry identity must survive list/queue selection independently of a live track and its reused ID. | Marks/actions | `OfflineStore.record`, `OfflineUi.downloadMark` / `DownloadAll`, `MuonApp` song toggle and `OfflineStore.add/remove` all address origin/ID. Online badges/actions need the same identity decision as playback; do not delete old data to unblock a new request. |
| Artwork | `DownloadArt.forArtwork` maps numeric live artwork URLs to retained files; `Artwork.loadArtwork` tries this before network. | Saved covers belong to saved entries. Live artwork must not reuse an uncertain saved cover even if the in-memory live identity cache is correct. |
| Moves/removal | `OfflineStore.watch`, `move`, `copy`, `removed` reconcile shelves/remove covers by numeric ID; pending #302 contains ownership/availability/byte controls. | New local handles must retain shelf/location and exact-operation ownership. | Queue/controller | `QueueModel.restoreUrl` parses numeric mediaId; QueueScreen removal/Undo reconstructs stream URLs. Pending #302 has occurrence-owned Undo. | A saved item's restoration must preserve its local provenance and occurrence identity, and must not become a network request for a reused server ID. Recheck external controller validation before adding any URI/handle route. |

`RetainedIdentityCharacterizationTest` already reads real disposable cache/index bytes for a changed-metadata reused ID, offline played-copy reuse, ordinary matches and different origins. These passing bug-characterization assertions are not a fix. Matching-metadata/different-audio is a useful additional control before designing any tag-equality guard.

## Proposed bite-sized work, not implemented

1. **Evidence/control only:** demonstrate indistinguishable saved/live tag records with different actual byte payloads in a disposable loopback/cache fixture. Retain existing different-origin/ordinary matching controls. Test-only; no phone acceptance needed.
2. **Local saved-entry model and read-only inventory:** propose an opaque, validated retained handle containing source kind/location/key plus saved metadata and Unverified status. Do not modify existing keys. Test legacy v1/v2, unknown records, duplicate numeric IDs, phone/card and played/explicit variants. This prototype can be test-local; final persisted schema requires review.
3. **First usable application boundary:** separately accessible Unverified saved entries, cache-only playback and exact-handle queue/Undo/actions, paired with live routing/marks/cover guards. Live selection streams when identity is unestablished; missing saved bytes fail visibly rather than silently fetching that live ID. Ship this coherent boundary together, not a routing-only change that makes saved data inaccessible. Pending codec/ownership changes must be deliberately integrated/reviewed; leave the PR open for user QA.
4. **Prospective downloads/copies:** design collision-free future keys and exact saved-cover ownership so retaining old A cannot block or overwrite new B. Existing keys remain readable. Revisit add/cancel/remove/move/listener ownership and optional-copy suppression. No silent rekey/deletion or bulk migration; do not claim a client-generated handle proves server content identity.
5. **Restart/offline/removable acceptance:** preserve listings/handles across restart, disconnected servers, same-ID reuse and unavailable/reinserted card; cover missing bytes, cancellation, Undo and controlled cleanup. Disposable actual cache/index tests plus user phone QA; full #179 lifecycle recovery remains a separate gate.

Steps 2–4 are proposed implementation scopes rather than settled API/schema or permission to merge app changes. Do not change external controller URI acceptance just to accommodate a local handle. No live server rebuild or user-library mutation. Inventory/decode failures must be reported conservatively; absence of a displayable record is not permission to delete retained bytes. Ordinary user-initiated cache eviction/removal policies still need explicit entry ownership and must not be confused with automatic identity cleanup.

## Manual acceptance when implementation exists

Download disposable A, arrange live B at the same ID (including matching tags but different audio), then confirm live B streams while saved A remains separately Unverified and plays offline without network fallback. Check live badges/covers, exact saved removal, new downloads not overwriting A, played copies, queue duplicates/Undo, restart and card availability. No test build for this report; #302 .623 remains the verified combined acceptance candidate for existing app fixes, not a #213 fix.
