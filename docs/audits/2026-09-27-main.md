## Findings addressed in this branch

### A1 — Unknown Canary history could suppress an unpublished app build

`tools/ci_scope.py::classify` compared main to a reachable Canary tag only when one existed. With no reachable tag, an app push followed by a documentation push could classify as docs-only. If the docs push cancelled the app build, no replacement build was requested. This contradicts the selector's conservative unknown-history rule.

Two tests using real temporary Git repositories reproduced the bad skip: no reachable tag after app changes, and a Canary tag existing only on an unrelated branch. The fix selects a full build when no reachable baseline exists. Existing tests still check that documentation after a published baseline skips APK work. This is publication reliability, not a finding that CI leaked secrets.

### A2 — Narrow-subnet discovery scanned addresses outside its subnet

`LanProbe.kt::probeCandidates` used a `/24` fallback for `/31`, `/32`, and invalid prefix lengths. A private host on one of those narrow links could therefore probe hundreds of unrelated addresses. The fix asks only the other `/31` endpoint, and returns no candidates for `/32` or invalid prefixes. Existing wider-network bounding and `/25`–`/30` behavior remain.

Tests cover both `/31` endpoint positions (including `.0` and `.255`), `/30`, `/32` and invalid prefixes. Treating both `/31` addresses as hosts follows [RFC 3021, section 2.1](https://www.rfc-editor.org/rfc/rfc3021.html#section-2.1). These are candidate-selection tests; no live network scan was performed. This does **not** explain the separately reported Benchmark fresh-install discovery failure.

### A3 — Device-transfer exclusions missed app storage domains

`data_extraction_rules.xml` excluded only `root` and `sharedpref`. `OfflineStore.create` now puts audio/artwork under `filesDir` and download/cache metadata in a database; those have separate backup domains. Android's [backup documentation](https://developer.android.com/identity/data/autobackup#EnablingAutoBackup) notes that some manufacturers allow device transfer despite `allowBackup=false`. Android 16's [`BackupAgent.onFullBackup` and `manifestExcludesContainFilePath`](https://android.googlesource.com/platform/frameworks/base/+/android-16.0.0_r1/core/java/android/app/backup/BackupAgent.java) traverse domains separately and prune exact excluded paths; excluding the root traversal does not exclude the separate file/database traversal.

The fix explicitly excludes all nine standard storage domains in both cloud and device-transfer rules, preserving the declared no-backup policy and manifest flags. A CI privacy-policy check failed on the previous XML and now verifies the manifest flags and complete exclusions. This closes a source-confirmed policy gap; it is **not evidence that any user's data was transferred**. Manufacturer-specific transfer behavior remains untested.

## Follow-ups, not fixed by this branch

### A4 — SD-card presence is captured at store creation

Tracked in [#179](https://github.com/averylicious/muon/issues/179).

Source-supported correctness finding, with device consequences pending reproduction. `OfflineStore.create` is the only place assigning `Store.card`; `get` retains the singleton. There is no mounted-volume refresh/observer. `Store.shelves`, `target` and `Shelf.completed` can retain a removed shelf/index, while a card inserted after creation never acquires a shelf. `SettingsScreen` also remembers initial card availability. This does not implement the documented promise that removal hides downloads and reinsertion brings them back during the same process.

Next: design cache/manager teardown and reattachment using the pinned Media3 sources, including active downloads/playback and queued moves. Keep old data intact, avoid two `SimpleCache` owners for one directory, and make availability/state observable. Regression coverage must distinguish index completion from storage availability. Manual SD QA: start without card then insert; eject idle/playing/downloading; reinsert; move either way; verify downloads remain and phone storage still works. Do not claim data loss from the current evidence.

Carried forward from `STATE.md` and Claude's report, not independently reproduced. Tauon and port 7814 were reachable, but scan found nothing until a manual address was entered. Verify permission timing, active interface and NSD/probe completion against current main; isolate Benchmark/Canary/Stable behavior. ### A6 — Additional review questions

- Download index reads in main-thread listeners (`OfflineStore.record`, `removed`, `watch`) may affect responsiveness during bulk operations. No performance measurement yet; not a confirmed jank cause.
- Check recovery when publication leaves a draft/tag but fails before publishing. A reachable tag alone is the selector's baseline; release completion must be assessed separately.
- Same-repository branch writers can modify Gradle/workflows that receive both signing identities. This is the documented trusted-writer boundary, not fork secret exposure. Audit future protection/secret-isolation options without silently changing signing or update channels.
- Dependency checksums/locking/advisories and the full resolved dependency graph still need their own assessment. Pinned action commits and a wrapper checksum are useful but do not establish complete supply-chain integrity.
- Review offline cache-miss network fallback, storage exhaustion and move/delete concurrency with pinned Media3 behavior before changing the storage layer. Preserve intended retained downloads after Disconnect.
