## Consequence and bounded next decision

There is **no single existing application mutex that covers these paths**. `@Synchronized OfflineStore.get` serializes initialization only. `DownloadMoveOwnership` owns publication for its registered batches; `PlayedCopyWork` owns its worker. Neither encompasses manager tasks, all index mutations, cache-internal effects, cover work or restart persistence. Do not broaden those locks and call the resulting design atomic.

The proposed admission contract must enumerate all writers and late completions, bind an exact cache/index owner and generation, invalidate stale record/census plans, and establish completion/drain and restart semantics. Determine which operations can be admitted through supported manager/cache APIs and which must conservatively refuse while ownership is uncertain. A durable counter or journal alone is not an atomic row-plus-file transaction; the #179/#230 preservation constraints remain.

Next bounded task: trace the manager add/merge/removal cancellation and completion paths together with source-reader/mover release acknowledgment, then evaluate a narrowly scoped prospective-saved-entry owner/admission protocol against disposable controls. Record any unsupported barrier before implementing an application API. Do not change legacy keys, edit Media3's internal tables, silently disable replacement downloads or add unused production scaffolding. User policy remains live streaming plus separately accessible Unverified saved copies when identity is uncertain.

This source map is not measured performance, a phone race reproduction or a production fix. Exact CI and device receipts belong in the [root QA checkpoint](../handoffs/2026-10-06-root-index-qa.md) and live PR comments; #302 remains an unmerged application dependency.
