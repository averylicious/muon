## Evidence that raises the priority

Muon retains the card's `SimpleCache` after removal. Its card download/content indexes live in the phone database. In the pinned [Media3 datasource sources](https://dl.google.com/dl/android/maven2/androidx/media3/media3-datasource/1.11.0/media3-datasource-1.11.0-sources.jar):

1. `SimpleCache.getSpan` calls `removeStaleSpans` when a cached file's observed length differs from the recorded length. `startFile` also removes stale spans when the cache directory is missing.
2. `removeSpanInternal` removes file metadata and calls `CachedContentIndex.maybeRemove`. Empty, unlocked content entries become pending removals from the content index.
3. `commitFile`, `applyContentMetadataMutations` or `release` can persist those removals. **`release` itself scans for stale spans before storing the index.** Releasing an absent card cache is therefore not an established safe teardown strategy.
4. On subsequent initialization, `loadDirectory` deletes files that `SimpleCacheSpan.createCacheEntry` cannot match to a content ID.

Potential sequence: remove card, access its retained cache and purge records, reinsert and perform an index-persisting operation, restart and load files whose IDs were removed. The remaining device questions include mount/path behavior, active locks and operations, which mutations are persisted, and callback ordering. The source supports this chain; the complete sequence has not been reproduced.

## Additional identity and service gaps

- The one download index named `card` is phone-side and is not keyed to a volume. Completed records for one card can survive when another card is inserted.
- `MuonCardDownloadService.getDownloadManager` falls back to the phone manager when no card shelf exists. Review how the pinned Media3 service helper handles two services using that manager before changing it.
- No shelf is created for late insertion. Settings, listing and routing retain stale availability.

## Requirements for the next implementation

Use a disposable regression scenario and the actual pinned cache implementation to decide a data-preserving lifecycle first. Re-check dependency versions from the build files; the source version above records this inspection, not a version prescription.

- Make volume identity and availability explicit in routing, listing, new downloads, moves, deletes and cross-shelf completion callbacks.
- Coordinate active readers, writers and service ownership. A mount check followed by a cache call has a race; pause callbacks alone do not prove safety after unexpected removal.
- Preserve recoverable content/index information across disappearance and reinsertion. Do not unconditionally release a removed cache, create a second cache owner for the same folder, or rely on a cached-length heuristic as proof the index is intact.
- Define same-card versus different-card reattachment and migration from the shared `card` download index.
- Keep the phone shelf usable; report unavailable storage accurately. Late insertion and live reattachment require more than an availability check.

An availability guard could be a separately reviewed containment fix, but must disclose that it does not solve mid-operation removal or already-purged metadata. Do not close #179 or claim safe hot-swap from that guard alone.

## Verification plan

First reproduce using disposable data and real Media3 cache/index code: remove/reinsert, mutate/persist, reopen, and assert previously downloaded bytes remain addressable. Pure decision tests can cover shelf selection, but cannot validate this cache lifecycle. Determine whether JVM testing can exercise the required Android pieces; otherwise use a separately authorized emulator/device setup.

User/device QA, when authorized, needs disposable copied audio for graceful eject and unexpected removal during idle playback, active playback, downloading and moves; same/different-card reinsertion; late insertion; online/offline behavior. Never use the user's only copy to reproduce a possible deletion path. Keep runtime reproduction and a fix's verification distinct from the current source evidence.
