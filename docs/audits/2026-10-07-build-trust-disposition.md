## One advisory narrowed: Kotlin cache deserialization

Fresh [GitHub advisory](https://github.com/advisories/GHSA-r937-wjx7-w2jp) read-back identifies CVE-2026-53914 and Kotlin Gradle plugin versions before 2.4.20-Beta1. The general summary says unsafe build-cache metadata deserialization; it does not establish every Kotlin compilation is exploitable. Read the linked upstream [fix bf51df665b458fda7c3eaf436c4d88dc119d7ec6](https://github.com/JetBrains/kotlin/commit/bf51df665b458fda7c3eaf436c4d88dc119d7ec6): it filters classes/proxies in KAPT incremental-cache deserialization (`JavaClassCacheManager`), not a generic network request or annotation-processing-free compile.

At immutable Kotlin 2.2.21 tag commit `2146684dcba708e5a304758b41a9e4ec9c7eff71`:
- `plugins/kapt/kapt-base/src/org/jetbrains/kotlin/kapt/base/incremental/cache.kt`139–163 opens `apt-cache.bin` / `java-cache.bin` with ordinary ObjectInputStream and calls readObject before casting; catching errors afterwards is not a deserialization boundary. SHA256 `c2a393dea2c72caf3d7b841654ecc47b1a3c87b65d967f59618020be09349837`.
- `plugins/kapt/kapt-base/src/org/jetbrains/kotlin/kapt/base/KaptContext.kt`58–60 constructs that manager only when `options.incrementalCache` is supplied. SHA256 `ab9350d81f8cc834c627e55bda92f2d5cb7abec90b7ee5195bff37ee19c06783`.

Current Muon build declarations and three Gradle workflows have no KAPT/KSP/annotationProcessor application/declaration/task. No affected KAPT incremental-cache execution route is established in these inspected tasks. This is a qualified non-applicability observation for the linked fix path, not proof no other deserializer exists, a source-to-selected-binary equivalence check, or a global Kotlin/build-cache clearance. Arbitrary plugin/runner code remains outside this conclusion. Keep the selected-version advisory recorded; re-evaluate before introducing annotation processors/KAPT. No forced beta/compiler upgrade or suppression file is justified by this path alone.
