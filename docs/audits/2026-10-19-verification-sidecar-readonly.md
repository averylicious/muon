# Read-only metadata during Move verification

Cumulative #612 head0905bdb70e08b85a52dead0a196adbf2a7c9aeda. Codex GPT-6 / desktop, exact variant/effort not reported; implementation/source self-check, no independent review or Claude implementation.

`PartitionNativeOwner.openClosedSaveVerification` already suppresses native span touches, but its persistent content metadata was still opened writable and used exclusive transactions on every read. On API35+ it now uses the existing `PartitionContentMetadata(readOnly=true)` mode. Older Android retains its existing supported writable transaction path; creation, writers, ordinary reads and native SimpleCache/database ownership/release stay unchanged. Full exact metadata is freshly re-read at every existing boundary; no snapshot cache, TTL or omitted checks. Verification no longer has sidecar write authority on supported platforms. This is not a read-only replacement for Media3's native cache/index.

API evidence: Android15/API35 [SQLiteDatabase source](https://android.googlesource.com/platform/frameworks/base/+/android-15.0.0_r1/core/java/android/database/sqlite/SQLiteDatabase.java) exposes `beginTransactionReadOnly` and preserves outer read-only semantics for nested transactions. This existing Muon mode is guarded SDK>=35 and uses supported SQLiteSession transaction ownership, not raw BEGIN SQL. Actual Android17 implementation was not independently checked.

Pinned [Media3 datasource1.11.0 sources](https://dl.google.com/dl/android/maven2/androidx/media3/media3-datasource/1.11.0/media3-datasource-1.11.0-sources.jar), SHA256 a54ddd9858ed2de57e07c5461dcebdae7a53d92a60210a2a3f5bf501398a5e4a: CacheDataSource only applies content metadata mutations when writing to cache. Muon's savedCacheReader supplies no upstream or write sink. It therefore reads through the sidecar; native open/release guards, full digest/known close and target verification before EVERY source unlink remain mandatory and unchanged.

One composed regression on API34 and35 creates a real closed partition with chunked unknown metadata, opens the actual verification factory, checks SQLite's actual read-only mode where supported, reads/digests all audio while rechecking full metadata, closes the owner and requires unchanged sidecar files/journal/residency. It then verifies the ordinary factory remains writable and preserves unknown fields. Existing read-only corruption/changed-owner, Move failure/uncertainty and per-unlink guard tests are retained unchanged. CI is the first Android compile/run; no local Android build or device result yet.

No measured speedup or whole-process memory improvement claimed. Device acceptance should compare an uninterrupted disposable diagnostic Move on #612 with this successor using identical saved/native/audio/cover/original proofs, bounded batch/nested counters and restored volume. App acceptance remains OPEN; no activation, Stable release or experimental merge. Native SimpleCache open/release and all earlier #401 costs remain until actual measurements establish otherwise.
