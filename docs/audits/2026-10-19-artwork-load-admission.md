# Bound active display artwork loads before byte allocation

Cumulative #618 6cf78ebe92ee95b40a92bd4f6241047af91841ee; #253 memory follow-up. GPT-6 / Codex desktop, exact variant/effort not reported; implementation/source self-check, no Claude or independent review.

The12MiB finished-bitmap LRU does not limit concurrent4MiB response buffers or native decode/scale/encode intermediates. The display fetch used shared Dispatchers.IO with no artwork-specific active-load budget. Rapidly replaced rows and artist collages could therefore overlap several complete pipelines; coroutine cancellation cannot interrupt a synchronous native bitmap decode midway. Source-supported amplification risk, not a reproduced phone OOM or measured peak.

A shared two-permit coroutine semaphore now wraps the whole fetch before entering IO or reading saved/disk/network bytes. It remains held through actual response consumption/close, decode/scale, identity-checked cache publication and optional disk encode/write. A queued request can cancel without starting HTTP or retaining an encoded body; active work keeps its permit until unwinding completes. Memory cache hits stay immediate. No image is dropped merely because capacity is full. Existing4MiB body/dimension/sample limits, stale-identity rules, saved-copy-only cover route, cancellation/HTTP deadlines and finished-cache behavior remain unchanged. No new dependency or settings/storage format.

A permit counts an operation, not an exact byte reservation; finished/composed images, notification art and separately bounded saved-cover download work remain separate. Slow servers may make uncached covers appear later at two-way concurrency; scrolling cancellation/deadlines still apply. No absolute whole-process/native heap or speed claim.

One real fetch integration case reuses the existing held-body servers: hold two distinct HTTP loads, start a third, require no third HTTP body, cancel that queued request, finish the two actual decodes, then require a new third load to succeed exactly once. Finally releases bodies/cancels jobs and drains every fixture. Existing real-body cancellation/identity replacement and decode/cache/notification/cover tests stay.
