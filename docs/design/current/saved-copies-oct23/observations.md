## New user evidence

- Shuffle off/on Undo now works in initial testing; queue list no longer blinks. Record those results without claiming unrelated navigation or every duplicate/rapid-edit variant was individually tested.
- Fresh-data reproduction: user force stops/clears app data, connects to Tauon, plays a song, enables Even out volume in Settings. Gain is not audibly applied until Next then Previous returns to the same song. Follow-up confirmed by the user: both ON and OFF fail to affect current playback until switching to another track and returning. Treat this as a current-track application/event-state bug, not only an initial-disabled-control presentation issue. Desired: apply On/Off to the currently playing song without navigation; truthful readiness while reading loudness information. Do not reproduce by clearing either user's app/data without new explicit authorization.
- Saved copies has excessive introductory/warning text, repeated music-note placeholders and crowded Optimize/check/trash row controls. User requests cohesive M3E-inspired mockup with one vertical three-dot menu at right of every saved row.
- Screenshot shows one manually downloaded item with cover and automatically retained played items without covers; same displayed song can appear twice. User requests understandable organization. Equal titles/artists do not prove byte identity or permit deleting/merging records. Separate explicit downloads and automatic playback retention visually; retain exact handles and bounded paging.
- Optimize appears for a selected copy, then opens a dialog saying it is already current/unsupported with disabled confirmation. Offer only after confirmed current eligibility; preserve backend revalidation when executing.
- Remove is offered, confirmation accepted, then NotOwned refusal toast leaves the copy in place. User explicitly clarifies: Delete must normally honor their choice, not refuse arbitrarily or force OS Clear data. Unverified against Tauon is not a deletion prohibition. Genuine I/O/storage failures need a clear actionable result. If references actually share bytes, remove the selected reference safely while preserving other valid copies; physical cleanup must not damage unrelated audio. This is a functional requirement, not permission to bypass real ownership/path safety or erase all saved data.

## Source findings versus open diagnosis

Confirmed source: SavedScreen.kt mixes manual Download and Played entries, each exact handle, with verbose Unverified subtitle. SavedRow offers Optimize using coarse complete/migrationLocator/partition-presence predicates; SavedMigrationDialog.kt only later asks freshMigrationAvailable. The latter checks actual migration state/ownership/coverage, so a visible action can lead to a disabled dead end. SavedRow uses projected removable, while OfflineStore.removeSavedNow performs deeper dispatch-time ownership/route checks and may return NotOwned. A stale/incomplete projection is not the same thing as proven foreign bytes. Actual refusal reason for the user's fresh entries is not established from screenshots.

PlaybackService.kt already listens to the enabled preference and calls applyLoudness immediately, and also stores gain/applies it on selected audio Tracks changes. ReplayGainSettings.volumeFor returns unity if no current/typical gain exists. Existing ReplayGainSettingsTest covers preference math/reload, not live tagged first-stream arrival and service/UI toggle timing. The first-play metadata/event/identity path needs a targeted regression or authorized disposable runtime reproduction; root cause is not confirmed. Gating the UI alone must not conceal a broken update. Pending, untagged and available are distinct; always allow turning normalization off. Once metadata is available, switching on/off must affect current playback without skipping/restarting and without changing Android media volume or re-encoding files.

No app code, dependencies, storage data or phones changed for this investigation. No local Android build. Mockup is a proposal, not implemented or runtime-tested UI.
