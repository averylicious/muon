New-save preparation previously unioned all shelf index IDs/keys and cache keys into one Java HashSet. `SavedNameRegistry` replaces that extra holder with an operation-scoped private SQLite census/reservations. Every row/state and every shelf contributes names, including an unavailable card. Each exact name is encoded to UTF-16 BLOB using the existing tested catalog encoding: NUL, case, supplementary and unpaired surrogate code units remain distinct; no clipping/normalization. One prepared save's fresh IDs are reserved in the same registry. The complete census precedes request construction; transaction/statement closure precedes any command send. Read/disk/probe/close failures refuse the whole preparation without changing originals.

The dedicated no-backup database is Muon scratch, separate from Media3's schema/audio/catalog. Reservations roll back on success or failure and are never restart authority; closed instances refuse probes. SQLite page cache requested at256KiB, not a whole-process heap guarantee. One original name and encoded BLOB can still be large, and Media3 getKeys still makes a full per-shelf native-key snapshot. Those native lifetime/snapshot limits are REQUIRED separate work. This slice does not make deletion/move/remove-all censuses bounded or establish service delivery acknowledgements.
