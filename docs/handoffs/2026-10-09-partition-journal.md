Unwired private disk journal records exact key/token/source UID/directory and bounded16-row pages. Unknown schemas/row types/states refuse; stale claims and cross-key directory collisions never replace somebody else's row. Pending/verified/uncertain records remain unready after restart; a verified row cannot publish using a receipt loaded from a prior process. Fresh retry changes the candidate UUID and leaves the previous uncertain directory intact. Ready routing is read from the journal, never the reservation catalog.

The disabled coordinator copies and fully compares retained bytes/unknown metadata, closes the destination, reopens the same native UID, performs a fresh full comparison, requires another successful close, and only then publishes the ready record under unchanged caller-provided exclusion. Cancellation, changed bytes/metadata/identity, unknown close or journal failure preserve originals and uncertain target files. Unknown native ownership stops further admission in that coordinator. Source-alias targets are refused without releasing the original. The factory must clean up its own failed creation; the caller must hold source availability/writer/reader-removal/eviction exclusion and a cancellation/deadline checkpoint. This helper does not establish that production barrier itself.

No production caller or migration UI is enabled. Ready rows are not source-removal authority; consumers must revalidate destination native UID, volume and ownership before reading. The original cache/index/cover/request remain unchanged and readable; full request/cover handover and safely revalidated optional source removal are future work. SQLite FULL synchronization and transactions are used; physical power-loss/card behavior and timings are not established by JVM tests. Legacy full-index import peak remains explicit; per-resource admission/leases/complete Cache routing integration still required before Stable.

Pinned native metadata-only limitation: SimpleCache drops byte-less content metadata during empty-content cleanup/reopen. The publication coordinator therefore refuses such a replacement after its required reopen verification, preserves the still-held original metadata and never publishes Ready. A regression control covers this; a durable metadata-sidecar/layout solution is still required for complete migration, not a reason to discard or silently skip original metadata. This is another reason these helpers remain disabled.
