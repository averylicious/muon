ReadOnlyLegacySavedAudio now uses a separate ephemeral audio/display projection. It keeps only the native content-length scalar and bounded Muon song/origin display fields, skips unknown optional values without allocating their decoded copies, validates all field structure/names/duplicates/trailing bytes, and does not infer EOF from cached extents. Omitted oversized display tags propagate the existing saved-tag limitation marker. Exact migration continues through LegacyResourceProjection.read, preserving full metadata or refusing; its 512KiB input ceiling is unchanged. No source bytes or metadata are rewritten.

Playback input is explicitly capped at 1MiB BEFORE the blob reaches CursorWindow/Java; the ceiling also limits the input SQLite could materialize internally. This is not an incremental native blob API or an arbitrary-sized metadata solution. One process-wide nonqueuing decoder admission covers query/decode and releases after known failure/cancellation. Only bounded fields survive after it releases. Valid metadata above 1MiB, excessive field/name/fragmentation budgets, unsupported identity/schema and corrupt blobs still refuse intact. Eventual opt-in must report those unsupported resources rather than silently drop/adopt them. No measured heap/performance claim; native SQLite overhead is not authenticated or measured here.
