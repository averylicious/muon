## Factory and residency

`PartitionNativeOwner` is still UNWIRED. Each known allocation owns separate bytes/, index/native-v1.db and metadata/content-v1.db. Separate native DBs prevent an unrelated UID namespace in a shared legacy DB from being loaded before admission. Native schemas are created/updated only by public Media3 APIs. Fresh construction requires the current Copying ticket/reservation and a missing UUID directory. A distinct migration adapter can create only its own attempt and reopen that same known attempt after clean close; another adapter cannot adopt a partial/old directory. Ready playback requires the journal's exact allocation/UID, not the latest catalog reservation.

Existing ready/attempt opens require exact canonical non-symlink layout, existing native DB and sidecar, sidecar UID/key/budget admission, then #437's read-only native preflight BEFORE constructing SimpleCache. Missing or mismatched state refuses without recreating indexes/metadata or deleting originals. Available-volume checks surround lifecycle stages and all resource API calls. The token is an observation, not a mount lock, volume authentication or source writer/removal/eviction barrier; real production ownership remains necessary.

`PartitionNativeBudget.process` is shared by default across stores, pools and migration factories. At most six opening/open/closing/quarantined native attempts are admitted, with fixed slots and no waiting queue. Tests inject a separate budget only for isolated fixtures. All possibly live handles are retained in their occupied slot. A native-constructor/unknown-close/volume failure quarantines its slot and stops the affected owner; restoration alone never retries that close or silently frees capacity. Other already-owned instances can still cleanly close. No reset/deletion/forced eviction exists.

Before release the factory requires facade quiescence and an owned-active native preflight. Native release may prune stale spans, so inconsistent files must refuse BEFORE it runs. After clean release it validates closed index/files, reopens/checks durable metadata, closes its own index DB and only then returns capacity. Native release may log a persistence error rather than throw; these observations improve detection but are not power-loss proof. Migration still performs a full byte/metadata comparison after reopen and retains every source. Cached-file reader pins remain external and must stay live through clean DataSource closure; the factory cannot infer them from Cache API calls. Journal Ready is never deletion authority.
