`CacheMigrationControl` is a single-use synchronous attempt handle, not a scheduler or real app-wide barrier. Caller explicitly opts in one resource, executes off the UI thread and holds the existing source/volume/writer/reader/removal/eviction exclusion. It retains one scalar status and admitted payload size, without key/metadata, callback queues, Throwable or history. Atomic admission rejects duplicate/concurrent run of the same handle; cancellation is safe to request from another thread. Other independent handles still require the shared publication/coordinator exclusion; this component does not assert global single-flight.

Before any target reservation, bounded scalar extent inspection sums required copy bytes with overflow checks. Destination free bytes must cover payload plus configurable conservative headroom (default16MiB); a negative/unknown reading refuses. This is not a filesystem reservation or a guarantee against later disk-full writes. The caller must query the actual destination volume, not unrelated internal storage. Timeout is monotonic and bounded1ms–24h; checks before AND after the borrowed barrier observe cancellation/deadline changes raised by that callback. Cancellation/deadline are cooperative between operations, not hard interruption of a blocked native call. A durable Ready publication is the commit point; a later cancel neither reverses it nor authorizes source removal.

Existing publication keeps originals and uncertain targets on cancellation/failure and fresh retries allocate new directories. No automatic retry, restart adoption, deletion, app setting, executor/service, native cache default switch, UI progress percentage or production caller is added. Status is deliberately coarse: Waiting/Preparing/Running/Ready/Cancelled/Expired/Failed, with copy size rather than an invented byte-completion percentage.
