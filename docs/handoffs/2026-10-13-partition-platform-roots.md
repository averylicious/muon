Production-shaped preparePlatformPartition owns the settings receipt first, resolves only Android app-private/external-files roots and reuses the actual persisted preparer. Default initialization still does not call it. Root names are fixed; no persisted/editable absolute paths. Private storage uses StorageManager.getUuidForPath, removable storage uses the mounted non-emulated StorageVolume UUID. Callbacks re-read current identity rather than cache a mount snapshot. Fresh selection must match the already-open legacy card, never a newly inserted/unowned one; Resume matches the exact receipt UUID even if platform ordering changes. Missing/replaced/ambiguous/unsupported volumes, child path aliases and excessive platform directory counts refuse before root allocation. A phone-only receipt does not adopt a newly inserted card.

Five real-filesystem/JVM policy tests cover off-main/no-root allocation, fresh/Resume identity/order/replacement checks, unowned/ambiguous card refusal, phone-only preservation/private replacement and aliased/invalid/oversized platform inputs.
